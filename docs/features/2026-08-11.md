## TUI 根证书列表与上游信任

- 原因：部分内网 Git/HTTPS 目标使用私有 CA 签发证书，serve 的 TLS MITM 上游校验仅信任系统根与 webpki 根，私有 CA 目标握手失败。需要一个不写入系统证书存储的、进程内的根证书信任来源。
- 设计：TUI「根证书」分类按 `a` 输入本地 PEM/DER 路径导入，证书立即加密写入 hyperhub home 下的 `root-certificates/<fingerprint>.bin`，一个证书一个文件，不持久化源路径；`Config.root_certificates` 仅存 `RootCertificate { fingerprint, enabled }`，`fingerprint` 为 DER 的 SHA-256，同时充当身份与文件名。证书文件复用配置容器的 XChaCha20Poly1305 + Argon2id 体系，但使用独立子密钥标签 `hyperhub/root-cert/v1`；主密码变更时在保存前用新密码与新的 KDF descriptor 重加密全部证书文件。serve 启动时在主进程解密启用项，把 DER 传入 `TlsMitm::generate_with_root_certificates` 加载进 outbound `RootCertStore`，失败即启动报错，避免静默降级。列表直接显示从证书提取的友好名称（CN，无 CN 时回退完整 subject）与启停状态，不显示 ID 与路径；回车进入后编辑页直接展示指纹、启用以及主体/签发者/有效期/序列号/CA/SHA-256 信息，无需额外按键。TUI 对解密后的证书信息做增量缓存（仅对新导入证书执行 Argon2 解密），避免每次按键重算。
- 验证：`certificate` 覆盖 PEM 包、DER、非法文件、指纹、CN 提取与预览测试；`config_store` 覆盖导入/读取/改密重加密/孤立文件清理/错误密码拒绝；`http` 覆盖私 CA 握手信任与无信任拒绝；TUI 覆盖路径导入、去重、启停、列表名称、编辑页信息展示与列表渲染；`hyperhub-core` 77 个、`hyperhub` 23 个测试全部通过。

## 协议模块化与分层状态机重构

 - 原因：`handle_authenticated` 原先按端口/规则散落 if 分派（socks.rs 中 Http/Https/Git 三处），新增协议需要在多处改动；同时客户端代理流量（HTTP CONNECT/SOCKS5/absolute-form）缺少外层代理协议端到端保留的统一模型，导致 Git 443 明文/代理流量被误判为 TLS 等系列 bug。需要从第一性原理出发，把客户端对原对端说了什么协议建模为状态机首态：serve 对原对端说的协议必须与客户端一致，MITM 只替换被审计的最内层。
 - 设计：
   - 新增 `crates/hyperhub-core/src/protocol/` 模块组：`detect.rs`（`Detector` trait + `classify_ingress` 首包分类 + `builtin_detectors` 注册表）、`transport.rs`（`UpstreamTransport { Direct, Tunneled }` + `ConnectedUpstream`）、`handlers/`（每协议一个模块实现 `PayloadHandler`，内置 https/http/http_proxy/bridge 四个）。
   - 状态机分派表 `plan_for(ingress, decision, credential)`：`HttpConnect` → `HttpsViaClientProxy`（HTTPS 或 Git:443+HTTP 凭证），`PlainHttp` → `Http`，`Tls` → `Https`，`Socks5`/`Raw` → `Passthrough`；SOCKS5 在 `handle_authenticated` 内经 `negotiate_socks5` + `complete_socks5_connect` 预处理后接入统一分类。
   - `connect_for` 四分支如实填写 `UpstreamTransport`：配置/环境/亲和代理握手后 = `Tunneled`，直连 = `Direct`，取代旧 `associated_client_proxy` 的判定职责；审计 `connection_detail` 携带 `upstream_transport`。
   - 加协议 = 新增 detector + handler 模块并在 `builtin_detectors`/`builtin_handlers` 注册，`handle_authenticated` 不再按端口/规则散落 if；TLS 解密后内层再探测沿用 `serve_https_tunnel` + `classify_decrypted_stream`。
 - 验证：`classify_ingress` 五个单测（明文 Smart HTTP、CONNECT、TLS ClientHello、SOCKS5 greeting、SSH→Raw）与 `plan_for` 分派单测；`hyperhub-core` 83 个、`hyperhub` 23 个测试全部通过。
