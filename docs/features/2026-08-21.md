# 进程 Hook 筛选策略

- 新增独立的 `[process]` 配置，通过有序完整路径正则规则为新进程选择 `hook` 或 `skip`，未配置默认动作、策略缺失或判定失败时保持 `hook`。
- Serve 在根进程启动和已注入父进程创建子进程时实时执行策略判定；`skip` 根进程不注入 Agent，`skip` 子进程不修改创建参数、不注入且不继续自动接管后代。
- Windows Agent 的 CreateProcess A/W、内部入口和 NtCreateUserProcess adapter 提取并规范化目标程序路径，ChildProcess 插件只消费判定结果，现有四个插件 ID 和 Agent ABI 保持不变。
- Config TUI 新增顶级“进程”分类，管理筛选开关、默认动作和规则；沙盒进程观测显示 Hook 状态、规则来源及策略版本。
- Config TUI 将已注入进程观测从沙盒概览迁移到进程概览，并把进程配置拆分为“基础”和“规则”子页；基础只保留总开关与默认动作，规则页只管理路径正则规则。
- 修复 Config TUI 文本输入框的中间光标编辑，支持左右/Home/End/Delete/Backspace；进程规则 Enter 可直接进入编辑器。
- Firewall 默认动作初始化为显式 `pass`，界面只显示 `pass/deny` 两态，不再显示“未配置（pass）”。

# 子进程与文件用户态沙盒

- Sandbox 新增 `process-sandbox` 与 `file-sandbox` 插件，分别控制子进程创建和文件读写、创建、删除、重命名及内存映射。
- Serve 按 Agent 进程预编译统一 SandboxSnapshot，并通过已认证的持久控制管道主动推送配置更新。
- Config TUI 的沙盒域新增“子进程”和可编辑“文件”页面；两类沙盒默认关闭且默认 pass。
- 文件沙盒在 ntdll 层 Hook 文件、Section、句柄复制与关闭入口；该能力属于用户态策略与审计，不是不可绕过的内核安全边界。

# Linux 泛化适配

- 增加 Linux 启动器与动态符号 Hook 原型，保留 Windows launcher 与 Agent 行为；后续统一迁移为 Frida Core 启动注入与 Frida Gum Interceptor。
- Linux Agent 通过 libc/POSIX 动态符号入口接入 DNS、connect、文件、exec 和 mmap 基础拦截，直接 syscall、静态 ELF 和 secure-exec 明确降级为未覆盖。
- 控制端点在 Unix 使用 `$XDG_RUNTIME_DIR/hyperhub/control.sock`，缺失时回退 `/tmp/hyperhub-control.sock`；增加 target triple 检查、Linux 构建脚本和跨平台 CI。
- Linux x86_64 交叉检查与 release 构建使用通用 target/linker 能力，不依赖 Ubuntu 主机路径。
