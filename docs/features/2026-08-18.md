# 2026-08-18

## TUI 保存时重新探测 Serve 在线状态

- 原因：`serve config` 在启动时固定 `live`，若 TUI 先于 Serve 启动，后续保存只写配置不推送热更新，必须重启 Serve 才生效。
- 实现：`save` 保存时重新调用 `serve_is_running()`，Serve 在线则复用现有 KDF descriptor 并推送 `UpdateConfig`，离线则按原逻辑落盘并轮换 descriptor。
- 影响：先开 TUI 再启动 Serve 的场景，保存后也能直接热更新；已建立连接仍保持旧快照。

## 客户端代理命中 upstream 时改为替换上游

- 原因：HTTP CONNECT / absolute-form / SOCKS5 客户端代理流量被端到端保留，路由即使配置 `upstream` 也不会被使用，错误上游无法阻止访问。
- 设计：采用替换语义——内层目标重新决策后若路由配置 `upstream`，HyperHub 重新 `connect_for` 到该上游建立到真实目标的隧道，不再复用客户端原代理链路；HTTP CONNECT 由 HyperHub 自回 `200 Connection Established`，明文 absolute-form 转 origin-form 并剥离 `Proxy-Authorization`/`Proxy-Connection`。
- 实现：`HandlerContext` 增加 `upstream_tunneled`；新增 `proxy_https_via_tunneled_upstream`；`PrefixedIo` 增加 `into_parts` 保留 CONNECT 头后的流水线字节；SOCKS5 客户端代理命中 upstream 时也改为直接走配置上游。
- 验证：新增 `tunneled_upstream_serves_http_connect_without_original_proxy` 与 `tunneled_upstream_rewrites_absolute_form_to_origin`；`cargo test -p hyperhub-core --lib` 129 个、`cargo test -p hyperhub` 46 个测试通过。
