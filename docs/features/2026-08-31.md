# GitHub 自动构建与首版发布

- 新增 GitHub Release 工作流：推送 `vX.Y.Z` Tag 后并行构建 Windows x64、Linux x86_64 和 Linux aarch64 的单文件 CLI，汇总压缩包与 `SHA256SUMS.txt` 后自动创建 Release。
- 新增 Linux 交叉发布脚本，按架构校验并使用对应 Frida Gum/Core devkit，构建并内嵌 Agent；Windows 发布包同步包含项目 Apache-2.0 许可证和 Frida Gum 许可证。
- CI 增加手动触发、Cargo 缓存、格式检查和明确的公开仓库只读权限；Cargo 元数据和 README 统一指向 `ohmydevelop/hyperhub`。
- 发布资产使用稳定平台名称，并提供 `scripts/install.sh` 与 `scripts/install.ps1`，支持从 latest 或指定 Tag 安装 CLI。
- 一键安装脚本同时生成 `hsh` 快捷命令：Linux 自动选择当前 Shell（默认 bash），Windows 生成 `hsh.cmd` 进入受控 cmd。
- 增加根目录 `LICENSE`，并将公开文档中的内部域名替换为示例域名。
- 首版版本号为 `0.1.0`，发布入口为 `v0.1.0` Tag。

验证：GitHub Actions YAML 解析通过；`release-linux.sh` Bash 语法检查通过；`release.ps1` PowerShell 解析通过；`cargo fmt --all -- --check`、`cargo metadata --locked --no-deps` 和 `cargo test --workspace --all-targets --locked` 通过。当前 Windows Release CLI 正在被本地 Serve/Session 使用，未强制终止用户进程运行完整 `release.ps1`；Linux 产物由 GitHub Actions 环境完成首次实际构建。

# 沙盒错误动作

- 文件、子进程和网络沙盒新增 `error_action` 配置项，专门控制路径、目标或判定异常时的动作，默认值为 `pass`。
- 具体规则优先匹配；未命中具体规则时使用默认动作，默认动作仍视为一次有效命中；只有判定错误才使用 `error_action`。
- Config TUI 在网络、文件和子进程页面提供“出错动作”切换，并为允许的错误判定记录 `*_allowed` 审计事件。
