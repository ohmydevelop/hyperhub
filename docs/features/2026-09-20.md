# 2026-09-20

## TLS 与 SSH 首次使用信任（TOFU）

- 网关对需要 TLS 检查的自签名站点采用 Trust On First Use：首次成功握手时校验证书的主机名、有效期与握手签名，然后把叶证书按精确 `host:port` 加密保存；后续证书指纹变化立即拒绝并记录审计。
- SSH 首次访问会抓取并按精确主机/地址与端口保存主机公钥；后续相同密钥放行，密钥变化以 `ssh_host_key_mismatch` 拒绝。ptrace 只得到目标 IP 时，手工配置的主机名记录会通过解析结果与目标 IP 匹配。
- TLS 信任项复用原有加密证书存储。`root_certificates[].host` 为空表示全局根证书，存在时表示单主机 TLS 叶证书；相同 DER 可同时作为全局根和多个主机 pin，删除一个作用域不会误删仍被其他作用域引用的证书文件。
- Config TUI 中，导入本地 PEM/DER 仍创建全局根信任；输入 `https://host[:port]` 创建单主机 TLS 信任；输入 `ssh://host[:port]` 创建 SSH 主机密钥信任。所有记录均可查看、启停和删除。
- 自动信任与人工配置使用同一份加密配置、UUID、脱敏 `show` 视图和热更新快照，并写入 `tls_host_trusted_first_use` / `ssh_host_trusted_first_use` 审计事件。
- Linux backend Benchmark 新增真实自签名 HTTPS 与本地 OpenSSH 服务：验证首次自动记录、第二次复用，以及 TLS 证书和 SSH 主机密钥轮换后拒绝。

TOFU 能防止首次记录后的密钥替换，但无法从密码学上排除第一次连接当时已经存在的主动中间人。高安全场景应在首次访问前通过 Config 人工导入并核对指纹。

## 人类可读的配置审批

- `hyperhub approve` 不再把完整审批对象和 before/after 配置直接打印为 JSON；交互界面现在按与 Config TUI 相同的语义显示操作、位置、对象、UUID、字段、摘要和配置详情。
- 敏感占位符只显示名称和待输入数量，配置值继续脱敏；校验结果、审批请求 UUID 与精简技术定位仍保留，按 `e` 二次编辑时才进入原始 JSON Patch 编辑器。

## 审批密钥派生性能

- Config CLI 在一次 `patch`、`approve` 或直接保存流程中只执行一次 Argon2id；派生主密钥保存在进程内的 `Zeroizing` keyring 中，配置、审批队列和热更新证明继续通过独立 HKDF 标签隔离。
- 审批的 in-flight 前置写入与完成写入仍保留，崩溃恢复语义不变；优化仅消除同一密码和 KDF descriptor 的重复 Argon2 计算，不降低磁盘加密参数。

## Jev / Laya 智能阻断可行性探索

- 新增智能阻断架构调研：确定性规则优先，模型只对显式绑定路由追加拒绝；建议引入独立异步 guard 层和 provider-neutral System One 协议，不把远程/本地推理塞入同步 `PolicySnapshot`。
- JevShield 的三原语判定矩阵可复用到 HTTP 请求上下文；远程输入必须默认移除凭证、query 值、正文、环境变量和完整命令行。
- 新增 `scripts/benchmark-smart-guard-laya.py`，使用合成脱敏案例复现 Laya 本地性能与判定结果。
- 本机 CPU 实测 `laya-typed-decisions` 单次判定约 2.0–4.4 秒、峰值 RSS 约 2.86 GiB，并漏判凭证外泄案例；当前只适合离线评估或 observe，不能作为默认 enforce 后端。详细结果见 `docs/intelligent-guard-jev-laya.md`。

## 统一智能防护

- 新增可复用的 `protections` 配置，把本地数据保护与 System One 智能判定统一为独立顶级“智能防护”；普通路由、默认路由及沙盒规则均可引用，未设置引用即关闭。
- 本地数据保护在凭证注入和上游发送前扫描有界 HTTP 请求正文，检测 HyperHub 托管秘密、常见 Token、私钥、提示注入与同连接外部输入复用；未授权目标的高置信度秘密、大正文或不可扫描编码可在 enforce 模式直接拒绝。
- HTTP 响应在转发同时旁路生成内容哈希、提示注入标签和滚动来源指纹；后续上传只保存并比较哈希，不持久化原始正文或命中片段。
- 智能判定支持 TypeSafe、OpenRouter 和 HTTPS/回环 HTTP 自定义 System One endpoint；远程只接收脱敏动作与本地 findings 摘要，支持 observe/enforce、低置信度与错误动作、并发限制、缓存、重试和熔断。
- Config TUI 增加“智能防护”分类，路由和默认路由可独立启停并选择防护配置；API key 继续通过 `SecretValue` 加密保存和脱敏审批。

## 智能防护 Benchmark 矩阵

- 新增 `scripts/benchmark-smart-protection.py` 与 `tests/fixtures/smart-protection/`，覆盖 Agent 本地预筛选、脱敏完整 argv、Mock Jev 决策、最终 allow/deny 和隐私断言。
- 矩阵覆盖安全命令、敏感文件外传、私钥复制、base64/管道、归档绕过、破坏性动作、提示注入、observe、Provider malformed/low-confidence/timeout 和误报样本。
- CI 使用本地确定性 Mock Provider，不需要真实 Jev Key；输出 JSONL、JSON 汇总、Markdown 报告和 TSV 检查结果。
- 基线门槛：本地预筛选 P99 小于 1ms、健康 Mock Provider P95 小于 50ms，所有敏感值不得进入 Provider payload。

## Agent 侧沙盒智能防护预筛选

- 进程、文件和网络沙盒规则支持 `protection` 与 `prefilter_policy`，按规则类型自动选择预筛选策略；未设置 Protection 即关闭。
- Agent snapshot 携带上述字段；新增本地确定性预筛选器，支持 `network_upload`、`sensitive_read`、`archive_or_encode` 和 `none`，以风险分数/硬阻断区分是否值得查询网关。
- 预筛选保留脱敏后的完整命令行参数结构：Authorization、Cookie、密码、Token 和 API key 值替换为 `<redacted>`；本阶段只完成本地判定与规则元数据传播，尚未新增 Agent↔网关智能判断控制请求。
- Chat 配置工具可为进程/文件沙盒规则写入 protection 绑定和预筛选策略。
