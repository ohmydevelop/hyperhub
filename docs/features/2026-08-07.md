# Windows x64 QBDI 指令入口拦截

- 原因：IAT 改写只能处理显式静态导入 Winsock、文件或证书 API 的程序，无法覆盖 Go 等通过运行时函数表调用 Windows API 的静态程序。
- 实现：Agent 将 Winsock、DNS、文件与证书 API 所在模块加入 QBDI 插桩范围，在真实函数入口注册地址回调；回调把 `RIP` 重定向到同签名适配函数并保留原始调用栈，由真实 `ret` 返回调用方。网络入口同时覆盖同步 `connect/WSAConnect` 与 Go 等运行时使用的异步 `ConnectEx`。
- 行为：不再要求目标 PE 存在可修改 IAT；Rust `agent-core` 的 socket/DNS/信任状态机保持不变。
- 线程：拦截 `CreateThread`，由 trampoline 在新线程内创建独立 QBDI VM；所有线程共享 Rust `agent-core` 的并发 socket、DNS 与信任状态。
- 动态模块：启动时插桩所有非 Windows 系统模块，并拦截 `LoadLibraryA/W/ExA/ExW`，将 Python 扩展、OpenSSL 和其他运行时加载库加入当前线程 VM。
- OpenSSL 信任：发现 `libssl` 后拦截默认和显式 CA 加载入口，在应用原有系统/文件信任后追加服务端下发的公开根证书，不向目标传递 CA 私钥。
- 边界：Windows XFG 目标仍在启动前明确拒绝，因为 QBDI 0.12.1 无法为重定向目标保留 XFG 元数据。fully-static 程序若直接发出 syscall，仍需 syscall 指令解码器；不经过 `CreateThread` 的私有线程创建路径需要单独适配。TLS pinning 不属于 CA 信任覆盖范围。
