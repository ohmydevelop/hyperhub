# Linux Frida Core 与 Gum 统一注入

- Linux 根进程改为 Frida Core 挂起启动、Session 激活、Agent 注入和恢复执行，不再依赖动态装载器环境变量。
- 新增 `unix_gum/`，通过 Frida Gum Interceptor 的描述符与 transaction 安装 libc/POSIX Hook，并保存 original trampoline。
- 增加 Agent 初始化就绪握手；Bootstrap 或 Hook 安装失败时不会恢复未受控目标进程。
- Linux 构建固定 Frida 17.17.0 Gum/Core devkit，按目标架构校验 SHA-256，并覆盖 x86_64 与 aarch64 检查。
- Serve 在 Linux 上校验 `/proc/<pid>/exe` 与进程启动时间，并在根进程退出或 PID 复用时自动撤销 Session。
- Linux 使用 Frida child gating 递归挂起 exec/spawn 后代；Agent 在调用前写入实时进程规则标记，启动器据此选择注入或直接恢复。纯 `fork()` 子进程只继承当前 Agent 映像，后续再 `exec` 的覆盖不在首期保证内。
- 可变参数 `open/openat/fcntl/ioctl` 改为 Gum InvocationListener 观测和修改调用参数/结果，避免用固定 Rust 函数签名替代 variadic ABI。
- Gum Manager 按解析后的目标地址合并同义符号，`open/open64`、`openat/openat64` 等别名只安装一次兼容 Hook。
- Linux 启动器直接使用官方 `frida-sys` bindings 封装 Frida Core，child gating 和后代注入均由平台 Rust 模块管理，不再维护 C shim 或派生注入 Crate。

# 单文件 Agent 发布

- Release 构建先生成平台 Agent，再将 Agent 字节、长度和 SHA-256 内嵌到 CLI，发布包不再携带独立 DLL/SO。
- 运行时使用当前用户私有的内容寻址目录原子释放并校验；Windows 持有禁止写入/替换的文件锁，Linux 从密封 memfd 注入。
- 根进程及后代注入前均验证 Agent 完整性；正式内嵌构建禁用 `--runtime` 外部覆盖，开发构建继续保留。
