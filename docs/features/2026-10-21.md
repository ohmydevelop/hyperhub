- 移除 `--api-key-file` 及其运行时兼容别名 `--password-file`，覆盖 `run`、`start`、`restart`、`serve`、`validate`、`export`、`import`、`config` 和 `chat`。使用旧参数时直接提示删除参数，并通过 `HYPERHUB_HOME` 选择实例。
- 所有入口统一读取当前 HyperHub Home 下的 `runtime/api-key`；`start` 派生 Serve 时也不再传入 API Key 文件参数。保留现有挑战认证、会话令牌、Key 文件权限检查和运行封套解锁校验；不把 Key 值放入命令行或目标程序的新增环境变量。
- 保留 `--admin-password-file`、`--input-admin-password-file`、`--password-stdin` 和 `--export-password-file` 的管理员验证与备份加密用途。目标程序自身的同名参数仍可放在目标程序名之后或 `run --` 边界之后。

## 在线升级的模块与生命周期基础

新增独立 `hyperhub-runtime` crate，提供版本化 C ABI、内容寻址的只读模块缓存、实际动态库加载、代际调用租约及 prepare/commit/abort/query/rollback 状态管理。默认保留最多四个旧代；仍有调用引用时拒绝继续升级，不强制卸载。模块析构和取消清理在事务锁外执行。原生模块需要受信任，ABI/摘要检查不提供故障隔离。

最小动态库源码位于 `tests/fixtures/upgrade_engine.rs`，已纳入 workspace 集成测试。测试通过同一输入得到不同版本的实际输出，覆盖旧调用保留、健康检查回滚、并发准备取消、重试、模块损坏和兼容性拒绝。

本阶段尚未接入 CLI、ptrace/Gum 或 Serve，不表示已有目标程序可以平滑升级。现有升级行为未修改。实现边界、限制及后续工作见 `docs/runtime-upgrades.md` 和 `PLAN.md`。
