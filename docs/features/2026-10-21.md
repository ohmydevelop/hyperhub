## CLI 自动管理运行时 API Key

- 移除 `--api-key-file` 及其运行时兼容别名 `--password-file`，覆盖 `run`、`start`、`restart`、`serve`、`validate`、`export`、`import`、`config` 和 `chat`。使用旧参数时直接提示删除参数，并通过 `HYPERHUB_HOME` 选择实例。
- 所有入口统一读取当前 HyperHub Home 下的 `runtime/api-key`；`start` 派生 Serve 时也不再传入 API Key 文件参数。保留现有挑战认证、会话令牌、Key 文件权限检查和运行封套解锁校验；不把 Key 值放入命令行或目标程序的新增环境变量。
- 保留 `--admin-password-file`、`--input-admin-password-file`、`--password-stdin` 和 `--export-password-file` 的管理员验证与备份加密用途。目标程序自身的同名参数仍可放在目标程序名之后或 `run --` 边界之后。
- 同步更新内置 Skill、配置参考、操作文档、远程构建脚本及 Linux/Windows 统一测试与 Benchmark 调用。历史发布记录保持原样。

兼容性：旧脚本必须删除这两个运行时参数；多实例在全部命令中保持相同 `HYPERHUB_HOME`。此前使用自定义 API Key 路径的实例，需通过 `hyperhub config` 或 `start --admin-password-file` 完成一次管理员验证，为当前 Home 初始化或刷新运行封套；不自动迁移其他位置的凭证。

验证：旧解析器实际未通过“移除参数”回归，修复后通过；新增回归覆盖 9 个入口的两个旧参数拒绝，以及目标参数边界保持。workspace 全目标测试通过（CLI 147、Agent core 22、core 189），最终 CLI 测试、隔离 Home 集成、顺序审批集成、Skill 合约、Bash/Python 检查、17 项 mock 智能防护测试和 Windows GNU 全目标编译检查通过。隔离 Home 回归验证自动认证、两个 Home 隔离、缺失 Key 不重建、错误 Key 拒绝、封套修复及启动子进程不依赖旧参数。本机已有用户 Serve，审批热更新子项按既有规则跳过；该子项及原生 Windows 行为由提交后的 CI 验证。远程 PowerShell 构建脚本仅静态审查，macOS 未实机验证。
