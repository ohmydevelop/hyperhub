# 2026-09-18

## Linux 静态程序最坏条件基线

- 当前阶段只保留全量 ptrace syscall supervisor，不启用 seccomp、eBPF、pidfd 或目标环境特性优化。
- 假设目标是无 `PT_INTERP`、无符号、无目标 libc、可能直接 syscall 的静态 Go/C/Rust 程序；静态分支不初始化 Frida，也不要求 Gum Agent runtime。
- supervisor 对所有 syscall 执行 entry/exit 跟踪，再按统一意图分派网络、DNS、descriptor、文件和进程规则，避免通过预筛选遗漏未知实现路径。
- fork/clone/exec 后代、connected UDP DNS、非阻塞 socket、file/process sandbox 和完整 Hook manifest 均由同一保底路径验证。
- 唯一硬前提是目标必须由 HyperHub 启动，且 Linux 允许父进程 ptrace 自己创建的同用户子进程；不满足时 enforce 模式明确失败。
- 后续优化必须分层进行：先优化全量 ptrace 本身，再把 seccomp-BPF 等运行环境能力作为可选加速，并用同一套语义测试证明与保底路径等价。

## Linux 执行后端边界

- 动态 ELF 固定使用 Frida Core + Gum Interceptor，并强制要求有效 Agent runtime。
- 无 `PT_INTERP` 的静态 ELF 不再解析或校验 Agent runtime，明确使用全量 ptrace syscall supervisor。
- `doctor` 和 `--dry-run` 输出具体 backend 及 runtime 是否必需；静态目标传入 `--runtime` 时明确警告并忽略。
- 静态集成测试会把 CLI 复制到不存在 Agent runtime 的目录后启动目标，防止后续回归为隐式 Gum 依赖。

## Linux 后端可复用 Benchmark

- 增加 `benchmark-linux-backends.sh` 作为动态 Gum、静态 ptrace、sandbox 与性能的单一入口。
- C/Go/Rust、动态 C 和大型静态程序进入指纹缓存，源码、架构或工具链未变化时不重新生成。
- 输出统一的 `suite.json`、`suite-report.md`、功能检查、性能 CSV 和 Hook reports。
- 旧静态覆盖脚本改为兼容包装；CI 与本地开发只执行同一套 benchmark。

## CLI + Skill 配置审批

- 增加返回完整 JSON 配置的 `show` 子命令，所有 inline secret 统一替换为 `<redacted>` 并报告 `redacted_paths`；`config show` 保留为别名。
- 增加 RFC 6902 子集 `config patch` 命令。
- patch 首次运行只返回变更计划和绑定当前状态的 approval token，不修改配置；新增交互式 `approve` 子命令供人工二次编辑、隐藏填写真实 key、复核脱敏 diff 并输入动态确认码后应用。
- 配置不存在时可由非交互 CLI 直接初始化；Serve 运行时应用后自动热更新。
- 增加 `$hyperhub-cli` Skill 和独立集成测试，覆盖错误 token、secret 脱敏、初始化、校验和在线热更新。
- LLM 工具链统一为 Skill + CLI + Shell。
