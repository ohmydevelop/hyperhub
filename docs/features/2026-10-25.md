# 2026-10-25

## 动态附加与解除接管开发分支

`dev/dynamic-attach` 独立开发 Linux ptrace、Linux Gum 与 Windows Gum 的运行中进程接管，目标预发行版本为 `0.3.0-alpha.1`。发布及主分支合并是两个不同阶段：预发行需完成同一提交的原生测试与压力验收，合并还需实际试用反馈。

- `attach` 与 `detach` 创建运行时审批，管理员在真实终端审核并输入密码。审批签名独立于 API Key 和运行时配置密钥，绑定进程创建身份、范围、后端、策略、执行器及封包。目标 Host 也验证签名，不能仅凭会话 Token 切换防护状态。
- 持久化状态明确区分接管、排空、兼容组件驻留、物理卸载、降级与清理未完成。存活连接、回调、线程退出处理、信任上下文及应用地址缓存会阻止物理卸载。允许业务连续性优先，不能通过杀目标或强制释放仍有引用的模块完成操作。
- 外部附加不取得目标进程所有权。ptrace 跟踪器不对外部目标启用 EXITKILL；跟踪器死亡明确报告失去拦截。管理器恢复使用新的人工审批，核对已封存的成员和基座，禁止对未知驻留状态叠加注入。
- 新 `run` 使用可撤销生命周期。Linux 的持久启动工作进程从创建时拥有跟踪关系，前台包装器单独接收原根进程退出码；Windows 使用有来源验证的一次性 keeper 交接。根进程退出不应提前撤销存活后代的会话。
- 运行时恢复封包的旧代密钥只在新代密钥下加密保留，审批签名种子不落盘。密码轮换链、冷重启后可验证的消费与完成凭据、Core 的真实子进程交接仍在开发；普通文件记录不能独立证明授权已被接受，不能据此宣称冷恢复或丢失 ACK 的全部路径已经完成。
- 开发构建默认使用 `.hyperhub-dev` 与实例私有 Skill，通过明确标签安装和更新。安装路径、全局 PATH、稳定快捷方式及稳定 Skill 分开处理。预发行不进入稳定版自动更新，也不成为 GitHub Latest。

源码 fixture 与平台统一 Suite 验证真实进程、审批、终端、连接和资源行为；常规测试与每后端至少 100 次循环、两小时混合压力分开验收。交叉编译不代替 Windows 或 aarch64 原生执行。具体命令、能力边界和状态含义见 [动态附加开发版](../dynamic-attach.md)，执行证据与未完成项见根目录 `PLAN.md`。

当前尚未发布。原 root 的 exec 以可信执行代次区分，即使 PID 和映像字节未变，旧代审批也不能直接复用；对应协议和真实回归仍在开发。跨进程地址缓存、并发成员捕获、原生 Windows/MSYS、最终同候选压力测试均需继续验收，历史候选的局部通过不替代这些门槛。
