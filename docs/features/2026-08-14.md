## 插件驱动的同源路由：移除 protocol/action，新增默认路由

- 设计：`RouteRule` 只保留进程/目标/端口匹配 + `upstream`（None=直连、Some=代理）+ `deny`（bool）+ `plugins`；删除 `RouteProtocol` 与 `RouteAction`。协议下探、是否 MITM/解析、凭证注入与审计全部由插件 `protocols` 驱动（http/ws 插件才解密/解析，否则透传）。
- 默认路由：新增 `Config.default_route { enabled, deny, plugins }`，语义为"优先级最低、match-all、不可删除"；未命中任何规则时应用其 deny+plugins（`deny=true` 即白名单 fail-closed），禁用则纯 passthrough。`default_action` 字段移除，其职责并入默认路由。
- 语义变化：不再按协议区分同 host 的 git/web 规则；git-over-http 视为 Http 载体，`PluginProtocol::Git` 仅表示 9418 原生 git；无 http/ws 插件的 HTTP(S) 不再解密而透传。环境代理选择改为按端口启发式（80→HTTP_PROXY、443→HTTPS_PROXY、其它→ALL_PROXY）。
- 验证：`cargo test --workspace` 全绿（hyperhub 24、agent 7、core 101）。
## 证书导入支持按 HTTPS 主机抓取 CA

- TUI：`根证书` 分类更名为 `证书`，并把 `环境变量` 移到列表末尾（长度易变）。
- 证书导入：统一入口支持三类输入——证书文件路径（PEM/DER）、`https://主机[:端口]`（主动 TLS 连接并捕获对端证书链中最接近根 CA 的一张后加入全局信任库）、`ssh://主机[:端口]`（本期明确拒绝并提示 SSH 主机密钥信任暂未实现）。
- 实现：`certificate::fetch_tls_peer_certificates`（关闭校验的 rustls 同步握手 + 自定义 verifier 捕获叶证书与中间证书）、`config_store::import_root_certificates_from_der`（内存 DER 直接加密落盘，供路径与主机两种入口复用）。
- 验证：`cargo test --workspace` 全绿（hyperhub 24、agent 7、core 101）。
## ssh:// 主机密钥抓取

- 证书导入的 `ssh://主机[:端口]` 入口：完成到 SSH KEX 回复的最小握手（curve25519-sha256），捕获服务器主机公钥（OpenSSH blob），存入 `Config.ssh_host_keys`（host/key_type/key_blob/enabled）。
- TUI `证书` 分类统一列出根证书与 SSH 主机密钥，`d` 删除、Enter 切换启用。
- 说明：SSH 数据面目前仍只透传，主机密钥暂作为信任锚存证，尚未在数据路径校验（SSH 终止/校验留待后续）。
- 验证：`cargo test --workspace` 全绿（hyperhub 24、agent 7、core 101）。
## SSH 主机密钥校验（探测式）

- SSH 层在透传前，若目标命中 `Config.ssh_host_keys` 中的受信记录，则另开探测连接完成到 KEX 回复的最小握手，校验服务器主机公钥；不一致则拒绝并审计 `ssh_host_key_mismatch`，未命中则按原样透传。
- 校验连接使用已解析的目标 IP，避免再次 DNS 解析到不同后端。
- 说明：仍是“探测 + 透传”，非完整 SSH 终止 MITM；凭证注入、转录、端口转发拒绝等留待后续。
- 验证：`cargo test --workspace` 全绿（hyperhub 24、agent 7、core 101）。
## SSH 双向代理（MITM）

- 新增 `ssh_mitm` 模块：命中 SSH password 凭证插件时，对客户端充当 SSH 服务端（russh）、对真实服务器充当 SSH 客户端，注入用户名/密码认证，并在通道层桥接 exec/shell/pty/env/data/eof/close/window；端口转发默认拒绝。私钥凭证注入尚未实现，回退透传。
- 依赖：引入 `russh`（ring 加密，server+client）与 `rand010`（对齐 russh 0.62 的 rand 0.10）。
- 说明：已编译并跑通单测，尚未在真实 SSH 服务器上做端到端验证；主机密钥校验沿用 MITM 前的探测式校验。

## TUI SSH 私钥管理（生成/导入/预览/复制）

- 凭证插件的 SSH `PrivateKey` 方案新增三个编辑器字段：`生成 RSA 私钥`、`导入私钥路径`、`公钥预览/复制`；`SSH 私钥` 字段仍支持直接输入值或 `-` 清除。
- 核心新增 `ssh_keys` 模块：`generate_rsa_private_key`（生成 RSA-4096 OpenSSH PEM）、`import_private_key`（读文件并校验 OpenSSH PEM）、`public_key_info`（解析出 `ssh-rsa` 公钥行 + SHA-256 指纹），统一经 russh 重导出的 `ssh_key` 实现，避免 CLI 直接依赖底层密钥库。
- 导入路径以 `SecretValue::File` 保存（生成则为 `Inline`）；公钥预览弹窗支持 `c` 一键复制公钥到 Windows 剪贴板（新增 `clipboard` 模块 + `Win32_System_DataExchange`）。
- 说明：私钥认证的数据面注入仍由后续 SSH MITM 实现，本期仅完成 TUI 侧密钥管理与公钥导出，便于在 Git SSH 服务器上配置公钥认证。

## SSH 凭证多私钥 + 多密码重设计

- 配置：`PluginConfig` 删除 `ssh_scheme`/`private_key`，新增 `ssh_private_keys: Vec<SshPrivateKey>`（`name` + `value`）与 `ssh_passwords: Vec<SecretValue>`；顶层 `username`/`password` 仅保留给 HTTP Basic。SSH 凭证要求至少一个私钥或密码。
- 运行时：SSH MITM 从客户端 `USERAUTH_REQUEST` 提取用户名，先按顺序尝试私钥公钥认证（RSA 用 `best_supported_rsa_hash` 选 sha2），全部失败后再按顺序尝试密码认证；上游成功才接受客户端登录，全部失败返回明确错误。
- TUI：SSH 凭证编辑器改为「私钥」「密码」两个列表；私钥支持路径导入/自动生成 RSA/多行粘贴 PEM，重命名、无边框公钥预览与一键复制；密码列表增改删且始终掩码。

## SSH 命令审计与“转录需要凭证”提示

- SSH MITM 现在会把客户端的 `shell_request`/`exec_request` 记录为 `ssh_shell`/`ssh_command` 审计事件（含通道号与命令文本），便于在默认路由下看到执行了哪些命令。
- SSH 层命中 `ssh_transcript` 审计插件但缺少 SSH 凭证插件时，不再静默透传加密字节：额外写一条 `ssh_audit_requires_credential`（outcome=skipped）说明“SSH 转录需要配置 SSH 凭证才能解密会话”；连接仍按透传处理。

## SSH 交互式命令捕获（stdin 行缓冲）

- 除 `exec_request` 外，SSH MITM 现在对客户端 shell 通道的 stdin 数据做行缓冲，遇到 `\r`/`\n` 即写入 `ssh_command` 审计事件（`kind=stdin`，含通道号与命令文本），覆盖 `ssh host` 进入交互 shell 后手输命令的场景。

## 审计日志按天分片、归档与保留清理

- 审计日志由单个 JSONL 改为按 UTC 日期写入 `{stem}-YYYYMMDD.jsonl`，翻日/启动时把非当天普通日志 gzip 归档为 `.jsonl.gz`。
- `AuditPolicy` 新增 `retention_days`（默认 7，0=永久保留），作用于日志与 transcript 会话目录；旧的无日期后缀基础文件按 mtime 日期迁移。
- TUI「审计」分类新增“保留天数”字段。
