## 面向聚合分析的审计日志存储

- HyperHub 的核心分析对象是 session、connection 和 protocol event，因此没有照搬 Codex 的会话归档目录；审计事件固定采用 `<config-root>/audit/date=YYYY-MM-DD/hyperhub.jsonl` Hive 风格日期分区，DuckDB、Spark、ClickHouse 导入任务和日志采集器可按日期直接裁剪文件。
- 每条新事件都包含 `schema_version`、`timestamp_ms`、`run_id`、单次运行内递增的 `sequence`、`category` 和 `event`。`run_id + sequence` 可作为采集去重键；`session_id`、`connection_id`、`process_pid`、目标、协议、规则、结果、流量和耗时等公共维度固定在顶层，协议特有字段统一放进 `attributes`。
- transcript 是可能很大的二进制旁路数据，固定存入 `<config-root>/audit/transcripts/date=YYYY-MM-DD/<session-id>/...`，结构化事件只保存 transcript 元数据与路径；一次捕获在创建时固定日期，跨午夜不会拆散。
- 启动时兼容迁移旧基础日志、`{stem}-YYYYMMDD.jsonl[.gz]`、先前的 `YYYY/MM/DD` 目录和旧 transcript session 目录；目标冲突时保留源文件，绝不覆盖。历史事件不重写内容，通过缺少 `schema_version` 识别为旧格式。
- 旧日期日志仍 gzip 归档；过期审计只删除对应日志文件，transcript 才删除整日分区，并仅清理已经为空的目录。`serve --output <file>` 保持显式用户路径语义，不参与分区。

## 默认路由归入路由配置

- TUI 的“基础”分类承载全局运行与监听设置；默认路由作为路由列表固定首项展示，ID 使用策略决策与审计中已有的保留值 `default`。
- 默认路由是匹配链的内置兜底项，不允许删除或修改 ID，也不展示它不支持的优先级、目标、进程、端口和上游字段；仍可编辑启用、拒绝、凭证和审计插件。
- 普通路由禁止使用保留 ID `default`，避免审计聚合时无法区分内置兜底与用户规则。默认路由引用的插件在重命名时同步更新，仍被引用时禁止删除。
- 配置 TUI 推荐使用 `Space` 切换布尔值、枚举和引用选择，同时保留 `Enter/e` 的旧切换习惯；路由首页使用 `Space` 启停，`Enter/e` 进入详情，避免动作冲突。
- “监听”并入“基础”，集中展示全局模式、SOCKS5 地址和 Pending Session TTL；仅调整界面信息架构，不改变配置文件结构。
- 右侧对象列表按 `Esc` 先回到左侧分类列表，左侧再次按 `Esc` 才退出或触发未保存提示；`Tab` 仍保留双向切换能力。

## 审计配置统一为事件与内容转录

- 审计方案按协议固定展示两层能力：`HTTP/WS/Git/SSH 事件审计` 决定是否生成该协议的结构化事件，`HTTP/WS/Git/SSH 内容转录` 决定是否保存协议内容；字段按协议成对排列，布尔值统一使用 `[x]/[ ]`，WS 内容转录保留“关闭/帧/消息”三级模式。
- 事件日志和内容转录路径由 HyperHub 根据活动配置目录内部固定，TUI 只保留“审计保留天数”；旧配置中的 `audit.log`、`audit.transcript_dir` 仍可读取但会被托管路径覆盖，导出时不再写出。共享的 `body_limit` 在界面中称为“单项转录上限”，避免将其误解为只约束 HTTP 正文。
- 原生 Git 内容从 HTTP 的 `capture_body` 中拆出独立 `git_transcript` 开关，避免切换 HTTP 转录时连带改变 Git。旧配置未声明该字段时，仍兼容 `Git + capture_body=true` 的历史行为；一旦通过 TUI 编辑便写入显式值。
- HTTP/WS 的事件开关现在真正门控 `http_request`/`http_upgrade` 协议事件；原生 Git 开启事件审计后生成 `git_session` 汇总事件。连接生命周期日志仍独立保留，不与协议内容转录混为一谈。
- 内容转录开启时自动启用同协议事件审计，关闭事件审计时同步关闭该协议转录；配置校验拒绝协议与内容能力不匹配的组合。
- 内容转录方向在审计方案级拆为 `transcript_client_upload` 与 `transcript_server_response`，TUI 对应“转录客户端上传”“转录服务端响应”。两个方向对 HTTP、WS、Git、SSH 统一生效，避免每种协议重复两组选项；旧配置缺省为双向开启，行为保持不变。
- 关闭某个方向后，转发和双向字节统计保持不变，但该方向从捕获入口即被旁路，不创建空文件、也不先落盘再删除。内部元数据仍使用稳定的 `client_to_target`/`target_to_client`，界面只展示面向用户的“上传/响应”。
- 只要任一协议内容转录已开启，TUI 和配置校验都会保证至少保留一个方向；若两个方向预先都关闭，随后启用内容转录时恢复默认双向，避免产生“开关显示开启但没有任何输出”的无效状态。
