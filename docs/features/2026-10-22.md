## 常驻 Host 的认证 Engine 管理通道

- Serve 使用已有会话、操作系统提供的客户端 PID 和会话成员实例绑定 Host。Gum 必须由目标本身登记；Linux ptrace 必须由目标祖先进程登记，管理线程与原有 tracer 共存。
- 升级所有者命令使用独立用途的 HMAC、30 秒时间窗口和有界请求 ID 历史。重复请求不会重复投递，冲突 ID、满队列及离线 Host 会明确拒绝。
- Serve 到 Host 的命令使用会话认证和每次连接的新 nonce。Host 在加载原生模块前验证命令证明，旧连接上的命令不能重放到新通道。不新增 API Key 参数或凭证环境变量。
- 状态区分 accepted、delivered、acknowledged 和 unknown。连接中断不能作为成功或回滚依据。`status --json` 增加每个 Host 的 PID、进程创建时间、成员实例、版本、引用和事务状态；状态中不包含会话 Token 或 API Key。
- 汇总状态限制事务历史数量，并用 `transactions_omitted` 明示省略数量。单 Host 明细与按事务 ID 查询用于确认具体升级结果；有界报告不会清除 Runtime 的幂等历史。控制命令、队列和请求历史均设置容量限制，满后拒绝新工作。
- Gum 后台管理线程不在空闲期间持有 Engine lease；模块加载、健康检查和回收不持有目标状态锁。ptrace 的目标、系统调用及描述符状态仍归原有 tracer 管理。
- 原生源码样例通过独立 SOCKS 对端观察新 Engine 报文，检查目标 PID/启动时间不变、既有 TCP 连接持续收发、损坏模块拒绝、不兼容状态 requires_restart，以及回滚后新连接恢复旧实现。统一入口为 Linux `scripts/benchmark-linux-backends.sh` 和 Windows `scripts/test-windows-hooks.ps1`；内部认证、重放、幂等、队列、确认错配与丢失使用 Rust 单元/集成测试。

当前为完整平滑升级计划的管理通道检查点。持久协调器、转发 worker、其他 Hook 能力组及全部子进程升级覆盖仍需完成后才能发布。本机已执行 Linux ptrace/Gum 原生用例；Windows 交叉检查已通过，原生 Windows 验证以对应提交 CI 为准。此记录不代表性能预算验收。

管理通道提交 `03e5e21` 已通过 [CI 39709798581](https://github.com/ohmydevelop/hyperhub/actions/runs/39709798581) 的全部 Linux 与 Windows 任务。Windows 统一入口实际执行原生目标在线切换用例，同时通过 67 个 Gum 测试；工作区阶段的该原生目标用例按设计先忽略，构建完成后由统一入口强制执行。

## 协调提交保留回滚代次

跨 Host 事务等待其他参与者确认时，首个 Host 的观察窗口不能先行耗尽。内部管理接口增加 `commit_held` 与幂等的 `begin_observation`：前者切换新调用并保留回滚代次，后者在协调器确认全组提交后启动既有健康观察窗口。重复启动不会延长已开始的窗口；重复旧事务不会修改新事务的观察。独立 `commit` 保持原有行为。

协调器失联会保留有界回滚资源，后续更新可明确拒绝；不会为了回收资源关闭现有连接。健康检查发现新实现异常时仍立即回滚。自动化回归使用零时长观察窗口，确定性覆盖部分提交失败、确认前保留、确认后回收、重复调用和健康失败；原生 Host Suite 同时执行新的管理命令。持久事务协调器本身尚未接入。

## 常驻 Serve 内的 Engine 事务协调器

- Serve 在发送参与者命令前，将意图和幂等 ID 写入私有事务日志并同步到存储。日志使用实例 API Key 和独立用途 HMAC 验证，单写者文件锁阻止多个协调器同时修改。口令变更不改变事务认证密钥。
- 日志损坏、认证失败及持久化失败均阻止后续外部动作；已存在的文件不会被当作空日志覆盖。恢复请求必须重新验证磁盘记录，再向进程查询具体事务，不能将丢失确认推断为失败或重新提交。
- 全组提交确认后才开始统一健康观察。观察通过后先持久化全局完成决定，再逐个释放回滚保留；旧连接和异步调用仍持有原代次，排空期间允许后续兼容升级。
- Host 重新连接必须匹配后端、Host PID、目标 PID 和创建时间。状态查询读取独立发布的快照，不等待日志 IO；公开 JSON 不包含工件路径、缓存路径或待发送命令。汇总和明细均有界，并报告省略数量；正在进行的事务优先于旧的终态记录，不依赖事务 ID 的字典顺序。
- 后台任务可在真实取消后重新启动。原生目标集成测试会中断协调任务，通过认证恢复命令继续升级，并验证 PID、启动时间及旧 TCP 连接不变。
- 协调传输使用预留命名空间、独立容量和每个事务参与者的单调序号。只有日志不再需要且已确认或已失联的传输记录才能回收；序号水位继续拒绝重放。普通所有者命令的不可驱逐历史即使占满，也不能占用协调恢复容量。回归会先填满 4,096 条普通历史，再执行超过该数量的协调命令，检查未应用确认不会提前消失、旧序号不会再次投递。

十五项状态机回归覆盖日志和确认丢失、部分提交、健康失败补偿、错误密钥和日志篡改、重复事务、多代排空、进程实例变化及任务恢复。状态机测试使用模拟参与者；实际原生库加载与目标行为由既有跨平台 Host Suite 验证。转发 worker、安装 helper 和其他 Hook 能力仍属于后续开发，不能把本组件视作完整发布验收。

## 完整发布事务、转发 worker 与兼容性边界

此前段落记录各组件的阶段状态。此次将真实原生 Engine、转发 worker 和安装 helper 接入同一个发布事务，最终验收结果以本节后续记录和精确提交 CI 为准。

- 常驻原生 Host 保留系统 Hook、操作系统对象和不可替换的状态；可替换 Engine 通过 C ABI 执行网络计划、文件/进程/防火墙规则、证书拼接、子进程计划和脱敏动作。调用、系统调用完成、异步 DNS、套接字及 dup 继续持有原代次。原生模块使用显式 owner 生命周期，最后 owner 释放后才销毁缓存和卸载。
- fork 子进程在受控恢复入口重建锁、模块和代次引用，再完成认证登记后恢复目标。新子进程必须加入正在进行的发布事务；已生效的部署记录绑定基座指纹，不能将旧基座的 Engine 装进新基座。
- 常驻 Serve 保留入口认证、会话、Fake-IP、审计序号、连接取消和 TLS/SSH 身份；实际 TCP、TLS、WebSocket、SSH 转发由独立的版本化进程执行。Unix 使用 SCM_RIGHTS，Windows 使用 WSADuplicateSocket；Offer/Ready/Grant 区分接收准备与业务 IO 所有权。未知 Grant 结果不会重试业务 IO。
- 原有连接继续使用原 worker，多个旧代次可无限期排空。最多保留四个旧代次，资源未释放时拒绝新升级，不能靠强制断连回收。worker 控制链路失效不主动关闭已经授予的业务连接；会话撤销仍能通过常驻入口取消连接。
- 发布事务使用认证日志，CLI 退出后继续执行。准备阶段先在候选 worker 内验证真实 Engine 模块，即使当前没有受管理程序也不能跳过原生加载检查。全组健康观察至少 30 秒，随后持久化不可逆决定，再释放回滚保留、启动安装 helper。安装回执、文件摘要和旧连接排空分别确认。
- 安装 helper 校验源文件、原目标、暂存和恢复备份。Unix 原子替换；Windows 对映射中的可执行文件采用有界重试与备份恢复。暂存执行权限、签名作业及磁盘回执支持中断恢复。无法确认安装时保持 `installation_pending`，不能报告完成。

`hyperhub upgrade` 提交发布；`hyperhub upgrade status [id]` 查询，`hyperhub upgrade recover <id>` 恢复，`hyperhub upgrade abort <id>` 在全局完成决定前中止。`hyperhub status --json` 同时显示发布、每个 Host 和 worker 的代次、引用、进程身份与排空状态。认证仍自动读取当前 Home 的内部 API Key，不新增凭证参数。

兼容检查独立比较 ABI、状态 schema、Engine 操作集、Frida 版本、worker/installer 协议、目标平台，以及常驻原生基座和 Serve 基座的源码指纹。指纹忽略格式、文档和测试模块，保留生产代码语义；构建时校验嵌入 Agent/Engine 的原生基座标记，拒绝混入旧构建产物。指纹范围内的共享入口/管理代码改动采用保守策略，要求显式维护重启；纯 Engine 处理和 worker 业务代码位于可替换边界。增加未知 Hook、改变基座或状态契约会返回 `requires_restart`，不自动重启目标。

首次从 v0.2.12 或更早版本迁移，需要在维护窗口安装新基座并重启受管理程序。不能让已经注入的旧 Hook 自动获得新增原生入口。后续兼容更新才支持保留目标 PID、启动时间和现有连接。macOS 尚无受管理后端，不属于本次在线升级支持范围。

自动化入口保留 Linux `scripts/benchmark-linux-backends.sh` 和 Windows `scripts/test-windows-hooks.ps1`，强制执行真实原生 Host、真实多进程转发及私有 Home 的完整安装流程。性能源程序与冻结模型分别位于 `tests/benchmarks/engine-upgrade/` 和 `benchmarks/forward-workers/`；组件结果不替代完整产品验收，也不作为生产吞吐或尾延迟保证。

## 进程映像替换与原 root 退出后的管理

新 Agent 在 exec 后使用新连接 nonce，等待旧控制连接实际退出并加入原 session 的稳定部署或候选事务；启动登记、事务纠正和 ACK 共用 25 秒预算，完成持久入组前不恢复目标。进程创建时间不变不代表 Runtime 代次计数仍相同，协调器通过事务内容重新确认；候选选择与回滚、finalize 交错时继续完成同一组决定。

Linux ptrace 的已认证 tracer 管理整棵登记子树，原 root 先退出不终止后代的策略刷新、静态审计或智能保护查询。管理权仍绑定 tracer 的实际创建时间及原 Host/root，查询和审计继续检查目标成员资格。明确的业务退出码保持原值并正常退休，信号、未知退出及 Windows 异常状态继续参与升级失败判断。相关源码场景进入既有 Host Suite，最终支持范围和兼容指纹边界不变。
