## 常驻 Host 的认证 Engine 管理通道

- Serve 使用已有会话、操作系统提供的客户端 PID 和会话成员实例绑定 Host。Gum 必须由目标本身登记；Linux ptrace 必须由目标祖先进程登记，管理线程与原有 tracer 共存。
- 升级所有者命令使用独立用途的 HMAC、30 秒时间窗口和有界请求 ID 历史。重复请求不会重复投递，冲突 ID、满队列及离线 Host 会明确拒绝。
- Serve 到 Host 的命令使用会话认证和每次连接的新 nonce。Host 在加载原生模块前验证命令证明，旧连接上的命令不能重放到新通道。不新增 API Key 参数或凭证环境变量。
- 状态区分 accepted、delivered、acknowledged 和 unknown。连接中断不能作为成功或回滚依据。`status --json` 增加每个 Host 的 PID、进程创建时间、成员实例、版本、引用和事务状态；状态中不包含会话 Token 或 API Key。
- 汇总状态限制事务历史数量，并用 `transactions_omitted` 明示省略数量。单 Host 明细与按事务 ID 查询用于确认具体升级结果；有界报告不会清除 Runtime 的幂等历史。控制命令、队列和请求历史均设置容量限制，满后拒绝新工作。
- Gum 后台管理线程不在空闲期间持有 Engine lease；模块加载、健康检查和回收不持有目标状态锁。ptrace 的目标、系统调用及描述符状态仍归原有 tracer 管理。
- 原生源码样例通过独立 SOCKS 对端观察新 Engine 报文，检查目标 PID/启动时间不变、既有 TCP 连接持续收发、损坏模块拒绝、不兼容状态 requires_restart，以及回滚后新连接恢复旧实现。统一入口为 Linux `scripts/benchmark-linux-backends.sh` 和 Windows `scripts/test-windows-hooks.ps1`；内部认证、重放、幂等、队列、确认错配与丢失使用 Rust 单元/集成测试。

当前为完整平滑升级计划的管理通道检查点。持久协调器、转发 worker、其他 Hook 能力组及全部子进程升级覆盖仍需完成后才能发布。本机已执行 Linux ptrace/Gum 原生用例；Windows 交叉检查已通过，原生 Windows 验证以对应提交 CI 为准。此记录不代表性能预算验收。

## 协调提交保留回滚代次

跨 Host 事务等待其他参与者确认时，首个 Host 的观察窗口不能先行耗尽。内部管理接口增加 `commit_held` 与幂等的 `begin_observation`：前者切换新调用并保留回滚代次，后者在协调器确认全组提交后启动既有健康观察窗口。重复启动不会延长已开始的窗口；重复旧事务不会修改新事务的观察。独立 `commit` 保持原有行为。

协调器失联会保留有界回滚资源，后续更新可明确拒绝；不会为了回收资源关闭现有连接。健康检查发现新实现异常时仍立即回滚。自动化回归使用零时长观察窗口，确定性覆盖部分提交失败、确认前保留、确认后回收、重复调用和健康失败；原生 Host Suite 同时执行新的管理命令。持久事务协调器本身尚未接入。

## 常驻 Serve 内的 Engine 事务协调器

- Serve 在发送参与者命令前，将意图和幂等 ID 写入私有事务日志并同步到存储。日志使用实例 API Key 和独立用途 HMAC 验证，单写者文件锁阻止多个协调器同时修改。口令变更不改变事务认证密钥。
- 日志损坏、认证失败及持久化失败均阻止后续外部动作；已存在的文件不会被当作空日志覆盖。恢复请求必须重新验证磁盘记录，再向进程查询具体事务，不能将丢失确认推断为失败或重新提交。
- 全组提交确认后才开始统一健康观察。观察通过后先持久化全局完成决定，再逐个释放回滚保留；旧连接和异步调用仍持有原代次，排空期间允许后续兼容升级。
- Host 重新连接必须匹配后端、Host PID、目标 PID 和创建时间。状态查询读取独立发布的快照，不等待日志 IO；公开 JSON 不包含工件路径、缓存路径或待发送命令。汇总和明细均有界，并报告省略数量；正在进行的事务优先于旧的终态记录，不依赖事务 ID 的字典顺序。
- 后台任务可在真实取消后重新启动。原生目标集成测试会中断协调任务，通过认证恢复命令继续升级，并验证 PID、启动时间及旧 TCP 连接不变。
- 协调传输使用预留命名空间、独立容量和每个事务参与者的单调序号。只有日志不再需要且已确认或已失联的传输记录才能回收；序号水位继续拒绝重放。普通所有者命令的不可驱逐历史即使占满，也不能占用协调恢复容量。回归会先填满 4,096 条普通历史，再执行超过该数量的协调命令，检查未应用确认不会提前消失、旧序号不会再次投递。

十五项状态机回归覆盖日志和确认丢失、部分提交、健康失败补偿、错误密钥和日志篡改、重复事务、多代排空、进程实例变化及任务恢复。状态机测试使用模拟参与者；实际原生库加载与目标行为由既有跨平台 Host Suite 验证。转发 worker、安装 helper 和其他 Hook 能力仍属于后续开发，不能把本组件视作完整发布验收。
