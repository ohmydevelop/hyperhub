## 配置热更新：Serve 运行中可编辑，保存即推送生效

- 设计：以 `RuntimeState`（原子替换快照：Config + 编译后的 `PolicySnapshot` + 解析后的环境变量）为 serve 侧热更新载体；每个连接/控制请求开始时取一次快照，新连接用新配置，已建立连接保持旧快照。热更新失败时旧快照原样保留。
- 通道：CLI 经控制管道发送 `ControlRequest::UpdateConfig { proof, config_json }`；证明为用 `derive_session_auth_key(password, descriptor)` 派生的密钥对配置 JSON 做的 HMAC，serve 用启动时持有的同一密钥校验，防止本地其他进程伪造注入。校验通过后 `RuntimeState::apply` 编译新策略并解析环境变量，成功才替换快照，审计记录 `config_reloaded`。
- TUI：Serve 运行中不再只读——增/改/删/保存均可编辑，`Ctrl+S` 先写加密配置（运行时复用现有 KDF descriptor 保持派生密钥稳定，XChaCha20 每次随机 nonce，复用 descriptor 不影响安全性）再推送热更新；推送失败时提示"已保存到磁盘、重启 Serve 后生效"。密码修改仍要求停止 Serve（改密码会轮换 descriptor 与派生密钥，无法热生效）。
- 说明：根证书、监听地址等需要重建资源或重新绑定的项不在热更新范围，重启后生效。
## MITM 插件化：统一凭证注入与协议审计为 [[plugins]]

- 设计：删除顶层 `[[credentials]]`/`[[audit_profiles]]` 与路由上的 `credential`/`audit_profile` 字段，改为统一 `[[plugins]]` 对象（`kind=audit|credential|convert` + `protocols=[http|ws|git|ssh|response|message]` + 按 kind 渐进披露的参数）；路由用 `plugins = ["id", ...]` 引用，按各插件声明的 `protocols` 在协议栈对应层分派。
- 运行时：新增 `plugin` 模块（`PluginSet` 热路径视图 + `Plugin`/协议钩子 trait）；`PolicySnapshot::compile` 把路由插件引用解析为插件集合，`run_stack` 每层检测/精化后按 `(协议, kind)` 分派——凭证做 transform（HTTP 注入 Authorization/Cookie/Query），审计做 observe（HTTP body、WebSocket 帧/消息、SSH 转录、Git 透传），执行顺序固定"凭证 transform → 审计 observe"。
- 校验：插件 id 唯一；route 引用存在；每 route 每协议至多 1 个 credential + 1 个 audit；`convert` 拒绝加载；`response`/`message` 仅占位（对应检测层与协议转换留待后续）；credential 插件的载体与 route 协议一致（git 载体只允许 http 凭证）。
- 兼容：不提供旧配置迁移，旧加密配置与 TOML 需按新 schema 重建；`examples/hyperhub.toml` 已切换为 `[[plugins]]`。
