# Agent Hook 与回调插件解耦

- 将 Windows Gum Hook 安装集中到 `HookManager`，使用原生 Hook 描述符统一解析目标、安装 replacement/original，并输出必需 Hook 失败和可选 Hook 缺失报告。
- 增加冻结的类型化回调链，覆盖 DNS、连接、Socket I/O/关闭/非阻塞、证书库与证书链、Schannel 以及子进程创建；before/after 按注册顺序执行，支持短路、结果覆盖、panic 隔离和 fail-open/fail-closed。
- 将现有网络重定向、CA 信任和子进程接管逻辑注册为内置插件，A/W 与 ConnectEx 等原生 ABI 差异留在适配器中。
- 保留现有 Agent C ABI、配置和 serve 控制协议；不增加动态加载或文件系统 Hook。

## 出站 FirewallPlugin

- 增加独立 Firewall 配置和按进程编译的启动快照，支持域名、直接 IP/CIDR、端口、优先级以及 `pass`/`deny` 动作。
- 在 DNS 和 TCP 连接语义 Hook 链首位注册 FirewallPlugin；没有默认规则、插件未启用或快照无效时保持 pass。
- 为插件回调增加失败策略覆盖，默认 deny 使用 fail-closed，默认 pass 使用 fail-open；原生适配器统一转换 DNS、connect、WSAConnect 和 ConnectEx 的拒绝结果。
- Firewall 拒绝事件通过 Agent 有界队列异步上报 serve，不在 Hook 热路径执行控制管道 I/O。

## Firewall 热更新与注入进程观测

- 已注入 Agent 每秒拉取一次 Firewall 配置版本；配置热更新后以无锁快照原子替换规则，不需要重启目标进程。
- 默认动作从 pass/deny 动态变化时同步更新回调错误和 panic 的 fail-open/fail-closed 行为。
- Agent 心跳记录进程 PID、可执行文件、根/子进程类型和当前 Firewall 版本；超过 5 秒未上报的进程不再显示为活跃。
- `hyperhub status` 和 Config TUI 的“进程”分类展示活跃的已注入进程，TUI 每秒自动刷新并支持按 `r` 手动刷新。
