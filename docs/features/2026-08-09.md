# Frida Gum 纯 Rust 回调 Agent POC

- 使用校验过 SHA-256 的 Frida Gum 17.17.0 Windows x64 devkit，构建脚本自动下载、解压和校验，不依赖本机预装 Frida。
- `hyperhub_gum_agent.dll` 是 Rust `cdylib`，静态链接 Gum；通过最小 Gum C ABI 调用 `gum_interceptor_replace_fast`，Hook 回调、socket 状态、DNS Fake-IP、SOCKS5 握手和 Schannel 校验均在 Rust 中实现，不使用 GumJS、JavaScript 回调或 C/C++ 胶水。
- 当前覆盖 `getaddrinfo/GetAddrInfoW`、`connect/WSAConnect/ConnectEx`、`send/recv`、`WSASend/WSARecv`、`ioctlsocket/closesocket` 以及 Schannel 凭证与安全上下文入口。
- Schannel 使用控制面下发的公开 Root CA，组合系统 Root Store 后执行证书链、服务端用途和主机名校验；不修改系统证书库，也不把私钥注入目标。
- CLI 能识别 Gum 后端，允许 CFG/XFG x64 目标；当前目录运行时自动优先发现构建出的 Gum Agent。

验证结果：Windows 系统 curl 和 PortableGit curl 均在不使用 `--resolve`、`--cacert` 或 `-k` 的情况下请求 `https://www.baidu.com` 返回 200；未 attach 时连接真实 IP，attach 后连接会话 Fake-IP。静态 Go 构建的 `gh --version` 可正常启动退出，且无需逐线程虚拟机。

当前 POC 使用 Gum Interceptor 拦截稳定系统 ABI，并不是对目标的每条机器指令进行跟踪。绕过 Winsock 的直接 syscall 或私有网络实现仍需后续的指令/syscall 适配。

## 通用文件型 TLS 信任覆盖

- Agent 在目标主逻辑启动前从认证控制面取得公开 Root CA，并设置通用 `SSL_CERT_FILE`；不配置程序专属环境变量或进程规则。
- 临时 PEM bundle 合并 Windows 系统 ROOT、目标原有 `SSL_CERT_FILE` 和当前 HyperHub ROOT，避免信任 HyperHub 时破坏目标原有的公开 CA 信任。
- 该能力只覆盖主动读取 `SSL_CERT_FILE` 的 TLS 客户端；完全内置根集合、自定义验证器和 certificate pinning 不做程序特异性绕过。

## Frida-only 仓库收敛

- 删除 CMake、QBDI/Native Agent、仓库内全部 C/C++ 源码和旧启动基准脚本。
- Gum Agent 改由 Cargo `build.rs` 直接链接已校验的 `frida-gum.lib`，构建不再需要 C/C++ 编译器。
- Windows 发布固定为 `hyperhub.exe` 与 `hyperhub_gum_agent.dll` 两个运行文件，并附带 Frida Gum 许可证。
- Linux 旧动态装载原型已移除；非 Windows 平台现在明确报告尚未实现，而不再暴露不可验收的入口。

## HTTP 请求级路由

- 增加 `http_method` 和 `http_path_regex`，在域名/IP/端口连接路由之后对每个 HTTP 请求二次匹配。
- HTTP/1.1 keep-alive 与 HTTP/2 复用连接不会共享第一个请求的 authority/path 决策；每个请求独立选择凭证、审计规则或 deny。
- request route 禁止配置 upstream 和地址重写，避免把请求级条件错误用于已经建立的 TCP/TLS 连接。

## Serve 运行时可观测性

- `serve --debug` 将脱敏 JSON 审计事件实时输出到终端，同时保留原 JSONL 文件。
- `serve --output <file>` 可将启动信息和 `--debug` 实时事件从控制台重定向到指定文件；TOML 的 `[audit].log` 不受影响。
- 控制面增加只读 `GetStatus`，CLI 通过 `hyperhub hyperhub status` 或 `connections` 查询当前 session 和活动 TCP 连接。
- 连接快照使用 `session_id + pid + connection_id` 关联可执行文件、原始目标、内层最终目标、route、原始 HTTP/SOCKS5 代理及处理阶段，不返回 token、凭证或 CA 私钥；PID 防止同一进程树内不同 Agent 的本地 connection ID 冲突。
- TLS MITM 的客户端握手与真实上游握手分别增加方向和阶段说明，连接错误包含 session、connection、PID 与 phase。

## WebSocket 转录

- audit profile 增加 `websocket_capture = "off" | "frames" | "messages"`，默认关闭；开启时必须配置 `audit.transcript_dir`。
- `frames` 保存 TLS 解密后的原始 WebSocket 帧；`messages` 去除 mask、重组分片、记录控制帧，并按服务端握手结果解压 `permessage-deflate`。文本消息直接写入 JSONL，二进制消息使用 Base64。
- HTTP/1.1 Upgrade 与 HTTP/2 Extended CONNECT 共用限长双向转录；解析仅发生在旁路，在线转发字节不改变。
- 每次 Upgrade 使用独立 stream ID；完成事件记录上下行文件、SHA-256、原始大小、捕获大小与截断状态。
