# 移除路由请求级 HTTP 方法与路径正则

- 用户确认不再需要路由规则中的 `http_method` 与 `http_path_regex_ref`（`regex.http_path` 类别），删除这两项请求级能力；`RegexCatalog` 保留进程、命令、文件三类命名正则。
- `decide_http` 仅保留 URL 形式 `targets`（`host/path`）的路径前缀匹配：对 HTTP 家族请求按未解码的 `path_and_query` 逐请求判断，非 HTTP 协议退化为纯主机匹配；`is_request_scoped` 及相关请求级冲突校验一并移除。
- Config TUI 同步：删除正则 HTTP 路径类别、路由表单的 HTTP 方法与 HTTP 路径编辑行及相应测试断言。
- 文档同步：README 迁移表去掉 `http_path_regex` 行；`.spec/hyperhub.md` 与 `docs/architecture.md` 改为 URL 形式 target 路径前缀的单阶段描述；OKR 操作手册示例改用 `targets = ["api.example.com/okr/api/permission/query"]`。
- 破坏性配置变更：路由中的旧 `http_method`、`http_path_regex`、`http_path_regex_ref` 字段在加载校验阶段报错（需删除字段或改用 URL 形式 target 路径前缀），`[[regex.http_path]]` 分类在解析阶段即被拒绝，避免规则静默放大匹配范围；不提供自动迁移。
- 验证：`cargo fmt --all -- --check` 通过；`cargo test -p hyperhub-core --locked` 151 passed；`cargo test -p hyperhub --locked` 73 passed；`cargo test --workspace --all-targets --locked` 全部通过；`cargo check -p hyperhub-agent-core --features gum-agent --locked` 通过。
