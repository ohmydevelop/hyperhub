# Agent 启动性能埋点与注入就绪同步

## 原因

静态 Go 程序经过 QBDI 时启动明显变慢，需要区分 Agent 初始化、平台 Hook 注册、模块扫描、线程 VM 和 QBDI 主循环的耗时。Windows x64 远程注入还不能把 64 位 `HMODULE` 返回值截断为 32 位线程退出码，否则可能误判 DLL 加载失败。

## 实现

- 增加 `HYPERHUB_AGENT_TIMING=1` 时输出 JSONL 时序事件，默认关闭。
- 记录 Agent Core、平台 Hook、模块扫描、TLS 根初始化、首次连接、SOCKS 握手和线程 VM 事件。
- 增加 `scripts/benchmark-gh-startup.ps1`，统一比较原生 gh、不同 Hook 组和线程 VM 数量。
- Windows 注入使用 `HYPERHUB_LOADED_EVENT` 与 `HYPERHUB_READY_EVENT` 两级同步，不再依赖截断的远程线程返回值。
- 增加 `HYPERHUB_DISABLE_DISCOVERY_CONTROL=1`，允许基准服务使用独立控制管道而不抢占全局发现管道。
- 增加通用 Windows Native Agent：通过进程级 IAT、`GetProcAddress`、DLL 加载和 `WSAIoctl` 扩展入口覆盖静态/动态、无符号程序，默认不为每个线程启动 QBDI VM；QBDI Agent 作为非标准 ABI 回退。
- 发布脚本同时打包 Native/QBDI 两个后端，并拒绝将内联 Bearer/Basic 凭证打入发布包。
- QBDI 回退增加进程级模块快照缓存，并由 `LoadLibrary*`/`FreeLibrary` 失效；回退时模块枚举从每线程重复扫描降为增量刷新。

## 验证

- `cargo test --workspace --all-targets --locked`：28 个测试通过。
- Windows x64 QBDI Agent 构建通过。
- `gh --version` 基准：原生约 66 ms，纯 QBDI 约 3.14 s，全 Hook 约 5.97 s；完整模式记录 14 个线程 VM 和重复模块扫描事件。
- Native Agent 验证：`gh --version` 约 1.2 s，`gh api user --silent` 约 0.9 s，GitHub API 命中规则并完成脱敏 Header 注入；QBDI 回退仍可正常运行。
- QBDI 回退验证：线程 VM 仍保持覆盖能力，模块扫描事件由原先每线程重复降至 6 次快照刷新，缓存应用 15 次。
