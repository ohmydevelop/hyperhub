# 2026-09-20

## Linux 动态程序偶发绕过 Gum 网络 Hook

- 现象：相同的 `hyperhub run curl ...` 偶发直接返回上游 HTTP 401。失败会话已经完成认证并创建 Agent 运行目录，但审计只有 `session_auth`、没有 `connect`；说明请求未进入 HyperHub SOCKS/HTTP 凭证注入链路，而不是令牌配置错误。
- 最坏情况基线：Linux 动态和静态 ELF 现在默认统一使用 ptrace syscall 后端，不依赖标准 Gum Agent 注入是否持续生效。动态 ELF 仍可显式传入 `--backend gum` 使用 Gum 优化；静态 ELF 拒绝 Gum。
- ptrace 完整性：系统通过 NSS/systemd-resolved 解析域名时没有可观测的 DNS 报文，SOCKS 请求只能携带目标 IP。Serve 现在会在首个 TLS ClientHello 或 HTTP 请求暴露 SNI/Host 后重新匹配连接策略，使 URL/域名路由仍能启用 MITM、凭证、拒绝、重写和上游代理。仅插件变化时保留现有上游连接，需要重写或切换上游时才重连。
- TLS 信任：Session bootstrap 增加 Serve 根证书。ptrace 后端把系统 CA 与 HyperHub 根证书合并为权限 `0600` 的本地 bundle，并向常见 TLS 客户端注入 CA 环境变量，避免 HTTPS MITM 出现自签名证书错误。
- 回归：统一 Linux backend suite 增加动态 ptrace 的 fork/exec、posix_spawn/posix_spawnp 回归，以及源码形式的 `linux_http_credential_probe.py`。后者以 IP-form SOCKS 建连，只通过 HTTP Host/path 暴露路由，并断言占位 Authorization 被 Bearer 凭证替换。真实 DevBoard 命令在默认 ptrace 下连续 10 次返回 HTTP 200，显式 Gum 仍返回 HTTP 200。

## ptrace 活跃进程未显示在状态与 Config TUI

- 现象：Serve 状态中的 `process_count` 已包含 ptrace 根进程和子进程，但 `processes` 只从 Gum Agent 心跳生成，导致默认 ptrace 后端在 Config 的“进程”页面显示“暂无活跃的已注入进程”。
- 修复：会话成员现在是受管进程列表的事实来源；Gum 心跳只补充最近上报时间和 firewall 版本，不再决定进程是否可见。CLI/TUI 文案统一改为“受管进程”。
- 回归：新增无 Agent 心跳的根进程与子进程快照测试，并保留带 Agent 遥测的快照覆盖。该问题属于状态/TUI 展示，不依赖外部目标程序，因此使用会话单元测试而不是新增 Benchmark fixture。

## ptrace 既有会话未应用沙盒热更新

- 原因：Linux ptrace supervisor 只在目标启动时编译一次文件与子进程沙盒快照；Serve 热更新和 Gum 的 `SubscribeSandbox` 已生效，但 ptrace 没有刷新通道，导致同一 PID 持续使用旧规则。
- 修复：控制面增加经过 Session Token 与 root PID 校验的版本化 `RefreshSandbox`；ptrace supervisor 在 syscall entry 以 250ms 上限节流刷新，并在目标 syscall 执行前原子替换已编译快照，同时同步 Enforce/Observe 模式。刷新或编译失败时保留上一份有效快照。
- 举一反三：网络路由、防火墙和凭证仍由 Serve 在每条新连接上读取运行时快照；文件与子进程规则由目标侧执行，因此纳入 ptrace 刷新。既有连接、已经完成的副作用、已经读入内存的数据和启动时注入的普通环境变量不会追溯改变。
- 回归：新增源码 fixture `linux_ptrace_hot_update_probe.c`，在同一 PID 中先验证文件读取与 `/usr/bin/true` 执行成功，再通过真实 `config patch` + `approve` 热更新规则，断言后续读取和 exec 均拒绝并写入审计。

## Needle 环境变量值偶发偏离用户原文

- 现象：内嵌 Needle 在不同平台或 CPU 调度下偶发返回正确的 `set_environment_variable` 工具但猜错 `value`，导致端到端测试和真实敏感配置存在不确定性。
- 修复：环境变量名称和值均从用户明确表达中恢复；当输入包含 `NAME to VALUE`、`值是`、`值为` 或 `NAME=VALUE` 时，用户原文覆盖模型参数。模型仍负责意图和工具选择，不针对具体应用或变量名特殊适配。
- 回归：新增模型错误猜值时仍保存用户精确值的单元测试，保留真实内嵌模型端到端测试。

## Needle 在共享 CI 上启动超时

- 现象：Needle 子进程仍存活，但共享 Linux runner 在高并发测试负载下未能于 20 秒内完成模型映射和 HTTP 监听，导致端到端测试报 `timed out starting embedded Needle 3`。
- 修复：健康检查仍每 50ms 探测并立即识别子进程退出，仅把最长期限扩展到 60 秒；正常机器不会增加等待，低功耗设备和共享 CI 获得合理启动余量。

## Linux 平台测试仍传递已移除的 sidecar runtime 参数

- 现象：单文件 CLI 改为内嵌 Gum Agent 后，backend benchmark 已删除 `--runtime`，但 `test-platform.sh` 仍传递旧参数，导致 CI 在运行完整 fixture suite 前直接退出。
- 修复：平台测试统一使用内嵌 Agent，不再传递 sidecar runtime 路径；与 benchmark 当前公开参数保持一致。

## Linux 平台测试构建了外置 Agent CLI

- 现象：移除 benchmark 的 `--runtime` 后，平台测试仍以默认 external-agent feature 构建 CLI；显式 Gum 边界检查无法发现 sidecar runtime，导致性能阶段后退出。
- 修复：平台测试复用刚构建的本机 Gum Agent，并以 `embedded-agent` feature 构建与正式发布一致的单文件 CLI。
