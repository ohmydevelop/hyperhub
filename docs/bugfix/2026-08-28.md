# 子进程获取最新托管环境

- 注入 Agent 初始化时通过认证控制通道取得包含环境变量、代理地址、执行模式、TLS CA、防火墙和沙盒的同一份 Serve 运行时快照，不再仅依赖父进程启动时继承的托管环境。
- 安装新快照前按 `HYPERHUB_SESSION_ENV_KEYS` 删除上一代托管键，因此热更新中删除的变量不会残留；调用方的其他普通环境变量保持不变。
- Windows 子 Agent 在首次信任请求时可由 Hub 根据命名管道真实 PID 和已授权祖先自动登记，在主线程恢复前即可取得完整策略；父 Agent 后续登记会幂等补充进程策略元数据。
- 配置热更新只影响此后初始化的新进程，已经运行的进程环境不会被异步修改。

## Windows MSYS 子进程稳定性

- 修复 Windows Agent 在 MSYS/Cygwin 纯 fork clone 初始化期间强制挂起和注入，导致 Git Bash 卡住、Git Hook `fork: Permission denied` 以及间歇 DLL 启动失败的问题。fork clone 现在按其 ABI 特征透明放行，普通 exec/spawn 仍保持递归注入。
- Session 改为分别监控根进程和已登记后代，根进程提前退出时不再撤销仍有存活成员的 Session；最后一个成员退出后统一清理连接和运行时状态。
- 子进程注入失败审计补充可执行文件、失败阶段及 Windows 错误码，避免所有失败只显示为无法区分的 DLL 初始化错误。

## Windows MSYS/Cygwin fork Hook 覆盖闭环

- 不再仅凭 MSYS/Cygwin 模块与 child-info 直接旁路。Agent 现在 Hook 运行时导出的 `fork`/`vfork`，先向 Hub 申请线程级租约；内部 `CreateProcessW` 只有同时命中租约、完整 `_CH_FORK`、相同命令行和已加载运行时才保持原样。
- fork 子分支在运行时完成地址空间、DLL 和 atfork 修复并返回后，原子替换复制来的 Agent 状态和语义 Hook runtime，重新建立 worker、控制连接和策略订阅，并用 runtime generation、完整 native Hook manifest 和当前策略版本向 Hub 证明覆盖。
- Hub 为每个 Session 限制最多 64 个、最长 300 秒的准备租约；候选 PID 经父子关系和映像路径核验后立即监控，10 秒内未证明时 enforce 终止候选并使父分支返回 `-1/EACCES`，observe 保留进程并记录 `fork_child_uncovered`。
- fork 租约与 Session 成员共同参与生命周期：根进程提前退出不会清理仍在准备或证明中的 fork；最后成员退出且租约全部结束后才撤销 Session。实现不包含 `git.exe`、`sh.exe`、产品名或安装路径分支。

## Windows 交互目标 Ctrl+C 控制台恢复

- 修复 `hyperhub run cmd` 等交互目标收到 Ctrl+C 时，控制台事件同时终止 HyperHub 启动器，导致启动器来不及恢复控制台模式，后续 PowerShell 将退格显示为 `^H`、出现 `More?` 的问题。
- 目标进程创建完成后，启动器临时注册仅吞掉 `CTRL_C_EVENT` 的控制台处理器；目标在创建前继承正常处理器，仍可正常接收 Ctrl+C。目标退出后自动移除该处理器，并执行既有控制台模式恢复。

- 修复 Linux Gum Agent 构建路径遗漏 `std::env` 导入的问题，避免远程 Linux 原生编译在 `install_managed_environment` 处失败。
- 修复 Linux Agent 将 CA 临时文件统一写入共享 `/tmp/hyperhub` 导致 root 创建目录后普通用户 bootstrap 返回 `-4` 的问题，改为按 UID 使用私有运行目录。
- 修复 Linux 文件型 TLS bundle 未合并系统 CA，以及错误将 `SSL_CERT_DIR` 设置为 PEM 文件的问题；现在保留系统 CA，并将 `SSL_CERT_DIR` 指向当前 Agent 的私有目录。
- Windows 控制管道改为按当前用户 SID 命名，SOCKS 监听端口占用时自动选择同一回环地址的空闲端口，允许不同用户同时启动 Serve。
- 修复远程 Linux 发布测试直接使用共享 `/tmp` 作为控制 socket 父目录导致测试服务启动失败的问题，改用当前用户私有临时目录。
