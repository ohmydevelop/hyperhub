## 已完成解除操作的冷 Core 证明（源码待 Root 验证）

- 原 consumed/completions JSON 的信任仅存于原 Core RAM，冷启动后合法已完成 cleanup 无法恢复；从磁盘直接补回 RAM 则会把可修改记录提升为执行权。新增独立、有限大小的 completed-cleanup 证据：真实 possession 消费成功后保存现有 Core 签名 AcceptedOperationCertificate，管理员原签 grant 同时背书该精确 Core 公钥、manager claimant 和完整 scope；实际 session revoke 的 epoch 比较成功之后，原 Core 再签 domain-separated completion，绑定 acceptance、nonce、activation epoch、session/token 摘要及原 manager 身份。

- 冷恢复仅服务新鲜人工签名的 Detach cleanup，要求原 manager 已消失、target/exec epoch/session/token 完全一致且没有新的 RAM activation epoch；不导入旧 consumption、不注册成员、不复活 session。无 Core 公钥背书的旧内部 API 保留原 RAM-only 行为，不生成冷恢复权威。
- 新增六个顶层单元入口（其中一个是独立子进程 reader 夹具），覆盖冷进程 RAM 空、双签轮换后历史完成验证、接受/unsigned intent 不算完成、不同 session/token/实例/目标/epoch、签名和历史链篡改、新 activation 拒绝旧 proof，以及读 proof 不恢复执行权。该 Bug 属于内部状态/密码协议与持久化语义，不依赖外部目标程序可执行行为，因此使用模块单元和独立测试进程，不新建业务 Benchmark 样例。
