# GitHub Actions Linux 交叉构建失败

- 问题：`linux-targets` 在构建 `aarch64-unknown-linux-gnu` Agent 时未显式设置目标 linker，Rust 使用 host `rust-lld` 处理 AArch64 专属 `--fix-cortex-a53-843419` 参数，导致 CI 以 exit code 101 失败。
- 修复：在 `scripts/test-platform.sh` 的 aarch64 分支显式设置 `CARGO_TARGET_AARCH64_UNKNOWN_LINUX_GNU_LINKER=aarch64-linux-gnu-gcc`，让交叉构建使用安装的 GCC linker。
- 验证：Bash 语法检查通过；需推送修复后由 GitHub Actions 重新运行 `linux-targets` 确认远端交叉构建。

- 首次 `v0.1.0` Release 验证发现 Linux 发布工作流直接执行新脚本时因 Git 文件模式为 `100644` 返回 exit code 126；工作流改为显式通过 `bash` 调用，避免依赖 checkout 保留可执行位。

- Linux Firewall 失效：Linux Agent 原先只接收 Firewall 快照并用于网关连接重定向，未在 connect Hook 前执行域名/IP/CIDR/端口规则。现已复用统一 Firewall 匹配逻辑，在代理端点旁路后执行拒绝并返回 EACCES，同时上报 Firewall deny 审计事件。
- 验证：Linux Firewall 域名/端口与直接 IP/CIDR 匹配测试通过；需在 Linux 发布环境使用实际配置和 hyperhub run curl 完成端到端验收。

- Windows 文件沙盒无法解析路径时原先对读操作 fail-closed，导致合法程序（如 `glab.exe`）被拒绝。现由 `error_action` 决定并上报允许/拒绝审计事件；默认 `pass`，命中明确 deny 规则的行为不变。
- 验证：Windows Gum Agent 沙盒定向测试通过；完整 Gum 构建依赖本地 Frida devkit。
