## 隔离证书回归测试的存储目录

深度升级验证并行执行两个 Rust 测试进程时，已有根证书导入/重加密测试出现文件消失。测试虽然随机化了配置文件名，却把所有配置都放在系统临时目录，证书目录因此共同指向临时目录下的 `root-certificates`。一个测试进程执行 reconcile/cleanup 会删除另一个进程的证书。

该测试现在为每次执行创建独立的配置父目录，证书、源文件和清理均限制在该目录内。保持生产存储行为不变。修复前失败证据：`target/diagnostics/engine-control-regressions-final.log`。回归使用同一个现有测试在两个独立进程中并发执行，不增加无关目标程序或性能样例。

## 原生 Hook 首次获取快照与加载器锁互锁

完整 Linux Suite 在 Gum 目标 `_exit` 及另一轮 `sendmsg` 路径出现超时。隔离失败目标的原生栈显示：Agent 状态锁持有者首次进入 ArcSwap 时，线程局部存储的析构注册等待 ELF 加载器锁；另一线程持有加载器锁并经 Frida 分配器进入 mmap Hook，等待同一个 Agent 状态锁。退出函数本身不是特判依据。证据：`target/diagnostics/durable-coordinator-gum-exit-symbols.log`、`durable-coordinator-linux-suite.log`。

Engine 活跃代次和 Agent 文件、进程、网络快照改用仅复制 Arc 指针的短读写锁，获取路径不再初始化 ArcSwap 线程存储。交换和回收时不持有快照锁执行析构或原生代码。Hook 先克隆 Engine 并释放 Agent 状态锁，再初始化调用上下文；直接 C ABI 调用不注册不需要的线程析构。专用沙箱订阅线程与 Engine 管理线程一样在可信后台环境处理阻塞控制 IO，不占用目标 Hook 的代次。

最小源码复现 `runtime_loader_probe.rs` 通过真实 DSO 构造函数持有加载器锁，并在原生 pthread 首次获取 Engine 时形成相反锁序。构造函数源码、构建参数和断言均入库，注册到 Linux 统一 Suite。取 `7d25573` 的原始 Runtime 源码独立编译时，该样例被 10 秒 alarm 终止（142）；修复后完成。证据：`target/diagnostics/engine-loader-native-{before,after}.log`。目标程序的模块枚举/首次 mmap 并发也扩展到已有退出源码样例，统一语义用例从 46 增至 48。读写锁内不得执行模块卸载，旧代次引用继续决定回收时间。

修复后 Linux 完整 Suite 通过 48 个语义用例、13 个拒绝用例和真实 ptrace/Gum 升级；Gum 32 项测试通过。后续全工作区及 Windows CLI 交叉检查一度因工作盘空间耗尽失败，确认无编译进程及打开引用后只清理仓库的两处可重建增量缓存，恢复约 46 GiB 并通过 1 MiB 实际写入；受影响的检查重新执行。Windows 原生结果仍以修复提交的 CI 为准。
