# Windows 注入就绪状态误判

## 原因

启动器曾使用远程 `LoadLibraryW` 线程的 32 位退出码判断 64 位 `HMODULE` 是否有效。句柄低 32 位为零时会被误判为 DLL 加载失败，且 DLL 已加载但 Agent 尚未完成平台 Hook 注册时缺少明确同步点。

## 修复

- 使用 `HYPERHUB_LOADED_EVENT` 等待 Agent Core 初始化完成。
- 恢复目标主线程后使用 `HYPERHUB_READY_EVENT` 等待 QBDI 平台 Hook 注册完成。
- 超时或初始化失败时由 `SuspendedProcess` 终止目标并清理资源，不再读取截断的远程线程退出码。

## 验证

- `cargo test --workspace --all-targets --locked` 通过。
- Windows x64 `hyperhub_qbdi_agent` Release 构建通过。

# 构建时无法覆盖正在使用的 Agent DLL

## 原因

Windows 不允许链接器覆盖已加载到目标进程的 DLL。使用 HyperHub 启动的程序仍在运行时，`scripts/build.ps1` 固定复用 `build/agent/windows-x64`，导致链接阶段报出 `LNK1104`。

## 修复

构建脚本在配置 CMake 前检查 Agent 输出文件是否被占用。被占用时按 Agent DLL 的完整路径定位加载它的目标进程，输出进程名和 PID，终止这些进程并等待其退出，然后继续使用固定构建目录。无法释放文件时明确失败，不再切换输出路径。

## 验证

在旧 Agent DLL 仍由目标进程加载时运行 `scripts/build.ps1 -SkipTests`，脚本终止了对应目标进程，并在固定路径生成新的 Windows x64 Release Agent。

# Native Agent 误拒绝启用 CFG 的目标

## 原因

Windows 目标检查曾把 PE 的 `IMAGE_DLLCHARACTERISTICS_GUARD_CF` 同时解释成 CFG/XFG，并直接套用 QBDI 0.12.1 的指令重定向限制。即使选择不使用指令重定向的 Native Agent，系统 `curl.exe` 等启用 CFG 的程序也会在注入前被拒绝。

## 修复

- 将 PE 检查改为能力报告，单独从 Load Config 的 GuardFlags 识别 XFG。
- 根据实际 Agent 后端验证兼容性：Native Agent 允许 CFG/XFG 目标，QBDI 遇到 CFG 目标时给出切换 Native Agent 的提示。
- Native Agent 使用 `/guard:cf`、`/guard:xfg` 和 `/CETCOMPAT` 构建，确保 Hook 函数是有效的控制流目标。
- `doctor` 分别报告 Native/QBDI 兼容性，不再让回退后端限制默认后端。
- 删除裸 `curl.exe` 特殊搜索 Git 安装目录的兼容分支，所有目标统一按显式路径或 PATH 顺序解析。

## 验证

- 系统 `curl.exe` 被识别为 `cfg=true`、`xfg=false`、Native 支持、QBDI 不支持。
- 系统 `curl.exe -V` 通过 Native Agent 正常启动。
- 显式选择 QBDI 时在注入前拒绝，并提示切换 `hyperhub_native_agent.dll`。

# 系统 curl 的 Unicode Schannel 信任失败

## 原因

系统 `curl.exe` 通过 `SspiCli!InitSecurityInterfaceW` 获取 Unicode SSPI 函数表，原实现只替换了 ANSI 函数表，因此 Schannel 没有使用 HyperHub 的限定根证书。模块路径还可能以 `\\?\C:\Windows` 形式返回，旧过滤逻辑未能识别该前缀，错误扫描系统 `SspiCli.dll` 后会使原函数指针递归指向 Hook。

## 修复

- 同时覆盖 `InitSecurityInterfaceA/W`、`AcquireCredentialsHandleA/W` 和 `InitializeSecurityContextA/W`。
- ANSI/Unicode Schannel 共享相同的限定根链和主机名验证流程。
- 目标主模块即使位于 System32 也允许 Hook；其他 Windows 系统 DLL 在规范化长路径前缀后排除。
- 缓存的 SSPI A/W 函数指针使用原子方式替换，且不再修改系统模块内部表项。

## 验证

系统 `curl.exe` 经 Native Agent 请求 `https://api.github.com` 返回 HTTP 200，未使用 `--insecure`，Windows x64 Native/QBDI Release Agent 均构建通过。
