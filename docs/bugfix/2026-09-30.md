# Bugfix 2026-09-30

## Linux ptrace 破坏 Unix socket 非阻塞语义

- 现象：在 `hyperhub run bash` 中启动使用 Tokio/异步 Unix socket 的后台服务时，控制 socket 已创建但客户端探测持续超时；`codex app-server daemon start/restart` 因此报告 app server 未就绪。
- 原因：ptrace supervisor 为完成 TCP SOCKS 握手，无差别移除了所有 socket 的 `SOCK_NONBLOCK`、`F_SETFL(O_NONBLOCK)` 和 `FIONBIO`，连不应代理的 `AF_UNIX` socket 也被改成阻塞模式。
- 修复：仅对 `AF_INET`/`AF_INET6` 的流式 socket 暂存非阻塞状态；Unix socket、UDP 和其他描述符保持原生语义，并在 `dup` 与 fork 后继承完整 socket 元数据。
- 回归：Linux 动态探针新增 Unix socket 源码用例，覆盖创建参数、`fcntl` 和 `ioctl` 三条非阻塞设置路径，并注册到统一 Linux backend suite。

## Hook 点位状态语义审计

- 举一反三审计网络、descriptor、文件映射及 Windows 句柄生命周期 Hook，发现仅验证“点位命中”不足以保证参数、返回值和跨调用状态语义正确。
- Linux ptrace 现在向目标保留握手前的逻辑 `O_NONBLOCK` 可见性；descriptor alias 与 fork 后代共享 open file description 状态，握手完成或失败后都恢复真实内核状态；`close_range` 与 exec 的 `CLOEXEC` 清理也同步回收跟踪状态。
- Linux ptrace/Gum 的 `mprotect(PROT_WRITE)` 会重新解析重叠的文件映射并执行 write sandbox，避免先只读映射再升级权限绕过策略；Gum rename 同时检查源和目标。
- Linux Gum 补齐 `dup/dup2/dup3/F_DUPFD`、`sendto/recvfrom/sendmsg/recvmsg`、`readv/writev/pread/pwrite` 的状态/策略入口；Windows Gum 补齐 sendto/recvfrom 及 WSASendTo/WSARecvFrom。
- Windows rename 现在解析 `FILE_RENAME_INFORMATION(_EX)` 的目标路径，源 handle 和目标路径分别执行 rename 策略。
- Windows DNS 增加同步/异步 `GetAddrInfoEx*`、`DnsQuery*` 与 `DnsQueryEx` 结果关联；Linux Gum 显式 vfork+exec 后代与非零退出码进入统一回归。
- Linux 与 Windows 的 create/open 现在同时判定 create 与 write/read 语义，避免 `O_CREAT|O_WRONLY` 或对应 native disposition 只命中单一操作。
- Windows socket 与文件句柄状态改为仅在 close 成功后清理，失败的 close 不再提前丢失 Hook 状态。
- Linux 源码 fixture 增加非阻塞读取、`close_range`、只读映射升级为可写，以及 Gum rename 目标路径 deny 回归，并继续由统一 backend suite 执行。
