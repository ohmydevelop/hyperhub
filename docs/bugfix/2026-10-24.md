## 多线程退出与非主线程 exec 的 ptrace stop 竞争

旧候选的完整 Suite 在普通 Go 进程结束时偶发 GETREGSET ESRCH；隔离 Go 300 次复现两次，通用 C 多线程 exit_group 样例 91 次完成中复现十次。非消费式原生观察证实，ESRCH 瞬间尚无可 wait 的终态，之后会收到 EXIT 事件及真实 terminal 通知；不能把 errno 或 /proc 状态直接当作死亡证明。

仅对已登记任务的 GETREGSET ESRCH 保留第一次错误、syscall 阶段及 Engine lease，最长一秒等待期间不恢复该失败 stop，继续处理其他内核通知。EXIT 延续不可逆退出；非主线程 exec 使用原有 TID 转移和新镜像登记，成功后才清除等待。真实 terminal 通知负责清理并保留原退出码，其他 errno、未知任务和逾期均仍报错。成功取寄存器后才刷新并执行原授权流程，未增加免授权路径。

主代理审查、Supervisor 15 单元及完整工作区构建通过。固定节拍的私有优化候选实际通过 732 项：C 退出与非主线程 exec 各 200、Go 300、TLS 析构 16、native 控制 16；68 次实际进入等待后均恢复正确结果。初轮未经节拍的 118 个 EOF 容量失败保留：第 257 次启动触及既有 Engine Host 256 上限与离线记录两秒保留，后续验证预先规定每 128 次间隔 2.1 秒，没有失败重试或修改容量限制。统一 thread_exit 检查加入 130 项默认断言，顶层仍 28 项；冻结 embedded 候选的完整 Suite 正在执行。
