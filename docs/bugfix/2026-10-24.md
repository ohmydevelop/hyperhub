## Windows 匿名管道的空名称重开

精确提交 727bf9c 的原生诊断证实：严格文件失败策略下，CreatePipe 返回错误 5；NUL 读写、继承标准流的子进程和空标准流的子进程均成功。相同 PID 的审计显示空路径在生成句柄之前被按 Write 拒绝。Rust 匿名管道用已创建的 server pipe 作为 RootDirectory、空 UNICODE_STRING 调用 NtOpenFile，不能将该操作解释为未知磁盘路径。

NtOpenFile 现在仅在结构长度有效、名称确实为空，且 GetFileType 证明根句柄为 PIPE 时交给原 API；非空名称、绝对路径、磁盘、事件、无效或未知根继续走现有文件策略。保留 OS 成功或失败的原 NTSTATUS 及 Win32/WSA 错误状态，成功后清除旧路径标签。新增真实匿名 server/client 管道重开和字节往返测试，以及磁盘/事件/错误句柄/非空名称的反向控制。Windows GNU all-target 编译与格式检查通过，真实原生两项测试及三项重启场景仍等待新提交的 CI，尚不计为通过。
