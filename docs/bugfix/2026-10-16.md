# 2026-10-16

## 普通保存保持配置密钥，及时维护运行封套

- TUI 的普通保存复用现有 KDF descriptor 和密钥，不再因 Serve 停止而自动轮换；每次写入仍使用新的 AEAD nonce。显式修改密码才创建新代次，并在保存前再次确认 Serve 已停止。
- 保存时立即更新 API Key 加密的运行封套，支持自定义 API Key 路径；不再等编辑器正常退出才刷新。读不到现有 descriptor 或验证失败时直接报错，不重新生成参数覆盖原配置。
- 放弃未保存的密码修改时，保留最后一次已保存的密码；刷新运行封套前先验证密码确实能解密配置，避免错误密码覆盖有效封套。已认证审批保存也会刷新已有封套。
- 启动预检检查封套代次和配置可解密性，明确区分旧封套与 API Key 解锁错误，并提供管理员修复路径；不再把旧代次问题延迟到 Serve 子进程后只报告通用密码/损坏错误。
- 封套写入失败时明确报告“配置已保存、运行密钥未更新”，保留可重试状态；不把两份文件的写入伪装成跨文件原子事务。历史上已经过期的封套仍需用户一次管理员验证才能恢复。
