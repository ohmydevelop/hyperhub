## SSH 空闲连接的双向保活

用户反馈 SSH 客户端在空闲一段时间后直接断开，并明确要求正常连接不应因客户端使用方式或空闲而被代理切断。用户未提供精确空闲时长及断线错误；当前实例检查时没有活动 SSH 连接，现场原因尚未实测确认。

源码确认了两个缺口：MITM 接入侧沿用 russh 0.62.6 的默认 600 秒空闲回收，上游侧虽然设置了无空闲超时，两侧均未启用 SSH 保活。客户端发出的 SSH 探活在 MITM 接入侧终止，不能维持独立的上游连接。

两侧现均禁用基于空闲的会话回收，每 30 秒主动发送协议保活，使用有限的未响应阈值识别失联。主机密钥验证、凭证注入、审计和通道桥接语义保持原有边界；短时主机密钥探测仍保留自己的超时。未配置 SSH 凭证的加密透传继续使用无空闲计时器的双向字节桥接。

回归采用现有 Rust 测试框架和平台 Suite，不作性能达标声明：

| 触发条件 | 独立结果判定 | 入口 |
| --- | --- | --- |
| 不主动探活的客户端空闲超过旧的 600 秒边界 | 原通道仍回传完全一致的数据 | `ssh_mitm::keepalive_tests::passive_ssh_client_survives_the_old_ten_minute_idle_boundary` |
| 两侧对端均不主动发探活，保持无通道数据 | 每个周期两条传输均实际收到对端回复字节 | `ssh_mitm::keepalive_tests::both_ssh_transports_probe_passive_peers_without_channel_traffic` |
| 分别丢弃两侧入站密文，保留 TCP 而不发送 EOF | 保活失败后受影响通道结束 | `ssh_mitm::keepalive_tests::missing_keepalive_replies_end_the_affected_channel` |
| 加密 SSH 透传空闲超过 600 秒 | 原 SSH 通道继续传输一致数据 | `ssh_mitm::keepalive_tests::encrypted_passthrough_has_no_idle_session_deadline` |
| 独立进程客户端分别关闭主动探活、每 5 秒主动探活；上游有 45 秒空闲截止；保持 65 秒无应用数据 | 两种客户端的 PTY shell、exec、subsystem 三个通道均能恢复精确数据交换 | `forward_workers` 中 `external_ssh_clients_keep_idle_pty_exec_and_subsystem_channels_alive` |

外部客户端源码为 `tests/fixtures/ssh_idle_probe.rs`，通过 `hyperhub-core` 的 `ssh_idle_probe` example 构建，已注册到 Linux 与 Windows 的现有统一平台入口。测试仅使用本地回环、固定虚拟凭证及私有 worker。虚拟时钟覆盖长空闲与失联边界，真实进程回归覆盖独立 SSH 客户端经过 worker 的完整协议路径。

修复前的三个定向 Core 回归均实际失败；修复后的四项定向回归通过。已发布 v0.2.16 的真实 CLI 作为旧 worker 时，无主动探活和主动探活两种外部客户端均失败；使用修复后的 worker 时，两种客户端的三个通道均在 65 秒空闲后继续工作。完整 forwarding worker Suite 13 项通过；工作区全目标测试 619 项通过，26 项按声明留给平台或手动 Suite。Windows GNU 全目标交叉编译、格式、diff 和 Bash 语法检查通过。

源码提交 `1fe8f5c` 已推送，[精确提交 CI](https://github.com/ohmydevelop/hyperhub/actions/runs/41999115142) 的 Ubuntu、Windows、Linux targets 三项任务全部成功。原生 Windows 的最终 CLI 明确执行并通过新增独立客户端回归；四项定向测试和完整 worker Suite 也全部通过。macOS 未实机验证。

直接复现入口（PowerShell 与 POSIX Shell 使用相同 Cargo 命令）：

```text
cargo test -p hyperhub-core --lib ssh_mitm::keepalive_tests --locked
cargo build -p hyperhub-core --example forward_worker_probe --example ssh_idle_probe --locked
cargo test -p hyperhub-core --test forward_workers --locked external_ssh_clients_keep_idle -- --ignored --nocapture
```

证据保存在 `target/diagnostics/ssh-idle-*.log`，包含修复前后的实际失败/成功、两种客户端的独立结果、集中测试及交叉编译结果。独立客户端由 `forward_workers` 测试驱动生成本地 JSON 参数，无需真实 SSH 凭证。

本轮不连接用户真实 SSH 目标，不重启真实 Serve，不直接更新用户安装。源码修复不等于用户当前运行实例已经更新。
