# Bugfix

- 修复 Jev/System One Provider 使用 `https://.../v1` 基础地址时未补全 `/v1/systemone` 的问题。此前请求直接发送到 `/v1`，服务返回 404，若智能防护 `error_action` 为 `deny`，所有绑定规则都会以 `provider_error` 失败关闭。
- 保留已经填写完整的 `/v1/systemone` 地址不变；服务异常时是否放行仍由智能防护 Profile 的 `intelligence.error_action` 决定。

- 修复 SSH MITM 在上游凭证登录成功后仍拒绝客户端初始 `none` 认证的问题。现在会先完成上游认证，再接受客户端探测，避免没有本地公钥的 OpenSSH 客户端无意义地弹出密码提示。

- 修复自动升级在 `/tmp` 与安装目录位于不同文件系统时因 `rename` 返回 `Invalid cross-device link` 而失败的问题。升级器现在先把 payload 复制到目标目录，再执行同文件系统替换。

- 修复 SSH MITM 将客户端不要求回复的 `env` 请求强制以 `want_reply=true` 转发，导致上游拒绝 `COLORTERM`/`NO_COLOR` 后把失败响应错配给后续 `exec` 的问题；同时补充 X11 请求透传。

- 为 SSH MITM 增加 direct-tcpip 与 direct-streamlocal channel 的上游创建和双向桥接，避免客户端请求端口/Unix socket 转发时被 HyperHub 默认拒绝。
