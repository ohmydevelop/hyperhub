# 2026-08-10

## Windows TUI 字符重复输入

- 原因：Windows 终端会为同一次按键发送 `Press` 和 `Release` 事件，配置 TUI 未区分事件类型，导致两次事件都写入输入框。
- 影响：导入路径、密码和所有表单文本会显示为逐字符重复。
- 修复：仅处理 `Press` 与系统生成的 `Repeat`，忽略 `Release`，并增加输入框回归测试。

## TUI 对象无法完整编辑

- 原因：上游代理、凭证、审计模板和路由只渲染为摘要列表，进入编辑后也只开放了个别代表字段，并以导入 TOML 作为主要修改入口。
- 影响：用户无法在 TUI 中完成路由匹配条件、协议、动作、重写、引用及 Secret/Header 的新增和修改。
- 修复：增加对象钻取表单和逐字段编辑，新建对象后直接进入表单；ID 改名同步更新路由引用，Secret 始终掩码显示。导入/导出从 TUI 移至 `serve import/export` 命令。

## Web 路由误用明文 HTTP 处理器

- 原因：HTTP/HTTPS 合并为 Web 后，首次路由会暂用 Http 表示 Web；收到 TLS ClientHello 后未重新计算已命中的路由。此外，客户端原有代理发出的外层 `CONNECT` 也可能被当成最终明文 HTTP，忽略隧道内 TLS。
- 影响：`gh` 等使用 HTTP 代理访问 HTTPS 服务时收到 `http: server gave HTTP response to HTTPS client`，连接被中止。
- 修复：协议探测完成后使用真实协议重新执行路由决策；识别代理形式的 `CONNECT` 后将最终目标协议标记为 TLS，从而进入 HTTPS MITM/转发处理器。直接 TLS 和 HTTP CONNECT 两条路径均增加回归测试。
