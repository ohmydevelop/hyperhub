# 2026-09-22 Bug Fixes

## 智能防护未进入 HyperHub Agent/ptrace 完整链路

- 现象：智能防护配置和 Jev Provider 已存在，但 `hyperhub run` 的进程创建仍显示
  `process_decision_source=default`，审计中没有 `smart_protection_decision`。
- 原因：`SmartProtectionCheck` 只实现了控制协议和网关处理器；Gum 的进程 Hook 没有调用
  网关判断，Linux 默认 ptrace supervisor 也只执行静态 sandbox allow/deny。
- 修复：
  - Gum Agent 在本地预筛选达到查询阈值后，通过控制通道请求网关判断；
  - Linux ptrace supervisor 保留完整 argv 结构、脱敏敏感参数，并使用静态 supervisor
    专用的鉴权请求调用同一个网关智能防护引擎；
  - Jev deny 在 `execve`/`execveat` 返回前转换为 `EACCES`；
  - 网关写入包含规则、Profile、风险、置信度和决策来源的
    `smart_protection_decision` 审计事件；
  - `DecideProcessHook` 现在返回真实规则来源，不再固定为 `default`。
- Benchmark：`scripts/benchmark-smart-protection.py --transport hyperhub --backend jev`
  可使用无网络副作用的临时 `curl` 替身验证
  `hook -> prefilter -> gateway -> Jev -> block/pass -> audit` 完整链路。
