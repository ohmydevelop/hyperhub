
## 命令执行时不再读取加密配置，控制管道固定不可配置

- 原因：`hyperhub <command>`（run_target）在收到会话 challenge 后会读取本地加密配置的 `config_id` 与运行中的 serve 比对；本地配置与 serve 内存配置不一致（例如改配置后未重启 serve）时直接报 `the local encrypted configuration does not match the running serve`，即使密码正确也无法执行命令。
- 修复：客户端命令改走固定控制管道完成 challenge/proof 验证——直接从 serve 返回的 `challenge.descriptor` 派生会话认证密钥并计算 proof，不再读取本地加密文件；`Config.listener.control` 字段删除，serve 与 TUI 统一使用固定的 `DISCOVERY_CONTROL_ENDPOINT`（Windows `\\.\pipe\hyperhub-control`），控制端点不再允许在配置中修改。
- 验证：`cargo test --workspace` 全绿（core 104）；`named_pipe_parent_session_uses_automatic_authentication`/`registration_round_trip` 改用独立测试管道名而不依赖配置字段。

## 子进程环境块把 Windows 隐藏的驱动器当前目录变量当成非法名

- 原因：`build_environment_block` 直接迭代 `std::env::vars_os()`；Windows 的 `GetEnvironmentStringsW` 会返回 `=C:=C:\...` 这类以 `=` 开头的隐藏“驱动器当前目录”变量，名字包含 `=`，被误判为非法并报 `target environment contains an invalid name or NUL character`。
- 修复：构建子进程环境块时跳过名字以 `=` 开头的隐藏变量（其不属于真实环境变量，也不应传给 `CreateProcess`），NUL/空名/真实 `=` 分隔符校验保留。
- 验证：新增 `environment_block_skips_windows_hidden_drive_variables`；`cargo test --workspace` 全绿（core 104）。

## ssh:// 主机密钥抓取使用 russh 完成握手，修复 OpenSSH 服务端关闭连接

- 原因：`certificate::fetch_ssh_host_key` 手工实现最小 SSH KEX，固定假设 curve25519-sha256 并忽略服务端 strict-KEX/扩展信息协商；对 OpenSSH 9.6 等服务端会在发送 ECDH_INIT 后被关闭连接，报 `读取 KEX 回复失败: failed to fill whole buffer`。
- 修复：改用 russh 客户端完成完整传输层握手，在 `check_server_key` 回调里捕获服务端公钥后关闭会话；`key_type` 取公钥算法名，`key_blob` 取 `PublicKey::to_bytes()`（与原 K_S blob 格式一致），删除手工 KEX/报文解析辅助函数。
- 验证：对 `ssh://agent.example.com:22` 实测返回 `ssh-ed25519` 主机密钥；`cargo test --workspace` 全绿（core 104）。

## 默认路由命中时在审计中明确上报 rule_id=default

- 原因：默认路由启用时，未命中用户规则的连接会被应用 default_route 的 deny+plugins，但 `RouteDecision.rule_id` 仍为 `None`，审计/连接快照显示 `rule_id: null`，看起来像“没有命中任何规则”。
- 修复：默认路由决策与 HTTP 决策统一使用稳定的 `rule_id: "default"`（未启用默认路由时才为 `None`），审计动作仍由 deny/upstream 派生。
- 验证：新增 `default_route_reports_its_id_deny_and_plugins`；`cargo test --workspace` 全绿。

## SSH MITM 每次连接更换主机密钥导致 known_hosts 告警

- 原因：`run_ssh_mitm` 在每次连接时 `PrivateKey::random` 生成新的 Ed25519 服务端主机密钥，客户端每次看到不同指纹，触发 `REMOTE HOST IDENTIFICATION HAS CHANGED`。
- 修复：serve 进程启动时生成一次 SSH MITM 服务端主机密钥（`SocksService` 持有），经 `HandlerContext.ssh_mitm_key` 传入 SSH 层复用；同一 serve 进程内所有 SSH MITM 会话使用同一主机密钥，客户端不再每次告警。
- 验证：`cargo test --workspace` 全绿（core 106）。

## SSH MITM 主机密钥跨 serve 重启稳定

- 在“进程级稳定”基础上改为确定性派生：由配置主密钥（session auth key）经 HMAC-SHA256 派生 Ed25519 种子，生成 SSH MITM 服务端主机密钥。只要密码与配置 descriptor 不变，重启 serve 后主机密钥保持不变，无需再删除 known_hosts。
- `SocksService::new_with_debug_output` 增加 `ssh_mitm_master` 参数；`new`/`new_with_debug` 与测试沿用随机/固定 master。
