## Linux Gum fork 管理交接与恢复前策略

深度回归发现两种不同问题。ptrace 用例假定父进程的 `ORPHAN_PID` 总先于子进程的 `TARGET_OK`；原始完整 stdout 证明顺序可以相反。测试现按精确 PID 和继承连接数接受这两种顺序，并保持原有总等待预算。Gum 则存在实际交接缺口：父进程退出时，Core 可以自动恢复尚未接管的子进程；恢复前的 libc child 回调也会绕过新文件与连接的策略检查。旧构建在固定三轮源码回归中均实际失败，文件和新连接都被允许，无超时。

管理器现在在 fork 前建立有界、认证的交接预留，以 OS PID 和出生时间绑定父子身份；父进程须等子进程的 Core 会话被保留后才返回 fork，子进程须等运行时重建、Host 登记和后续 fork Hook 就绪后才继续业务。未完成预留不能被当作正常排空；死亡进程的历史授权和已断开的 Core 会话会被清理。libc child 回调在恢复前发起的新策略请求返回 `EACCES`，已授予描述符的异步信号安全读写保留。

实际 Agent 可能来自密封 memfd。Core 从模块自身的内存 ELF 导出表定位完整常驻接口并拒绝歧义，不依赖不存在的磁盘路径，也不把 `dlsym` 的依赖模块符号误认成模块自身导出。Core 的早、晚原生回调仅首次安装；管理器保持子会话的 gating 引用，避免在仍执行的 fork 回调中重新挂接。r10 使用与修复前相同的目标源码和测试，首轮及固定三轮均通过；父立即退出、fork/exec、策略、Host 注册和后续升级断言均实际执行。信号恢复边界、完整 Suite、最终跨平台 CI 和发布包验证仍须完成，不以此组件结果代替最终发布验收。


恢复期间还需防止应用信号处理函数提前执行。早期原生回调在 libc child 回调结束后保存并屏蔽该线程的内核信号集，晚期回调仅在完整发布后恢复原信号掩码；保留应用 child 回调对掩码的修改，不改变父线程。内核掩码、父线程不变及协议单元共四项通过，完整 Gum 37 项及工作区通过。独立源码目标由父进程在 fork 返回后立即发送 `SIGUSR1`，处理函数只执行异步信号安全的本地文件、socket 与 pipe IO；旧 r10 的真实处理函数允许两项永久拒绝的请求，新 r11 对两项均返回 `EACCES`，随后完整升级用例通过。新增的实际失败 fork 源码目标使用仅本进程的 seccomp 规则产生 `EAGAIN`，保留 Frida 所需线程和共享内存助手创建，不修改用户资源限制；具名回归检查预留取消与错误码，并由同一统一入口执行。
