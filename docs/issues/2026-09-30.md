# 2026-09-30

## Hook 能力边界与后续平台扩展

以下条目不是当前已声明 Hook 契约中的漏点，而是需要新增平台能力才能覆盖的边界：

- Windows RIO、`TransmitFile/TransmitPackets`、`WSADuplicateSocket` 跨进程恢复和直接 syscall 不属于当前 WinSock/ntdll Hook 契约；支持前需增加扩展函数表包装、跨进程状态传递协议和 Windows 源码 Suite。
- Windows OpenSSL/BoringSSL、自带证书库及 certificate pinning 不经过 Schannel/系统证书链 Hook；当前契约仅保证 Schannel 与系统信任 API。
- Linux 显式 Gum 是动态符号优化后端，直接 syscall、`openat2` 等无稳定 libc 导出的入口由默认 ptrace 后端保证；安全基线仍为默认 ptrace。
- Linux ptrace 通过 `SCM_RIGHTS`、`pidfd_getfd` 新进入进程的 socket 尚无主动类型发现；文件 descriptor 仍可按 `/proc/<pid>/fd` 执行策略。新增 socket ingress 需要远程 `getsockopt` 分类及源码 Suite。
- macOS 尚无与 Linux ptrace/Windows Gum 等价的运行时 Hook 后端，当前不宣称 macOS Hook 能力等价。

当前契约内已覆盖 Windows `getaddrinfo/GetAddrInfoW/GetAddrInfoEx*`、`DnsQuery*`/`DnsQueryEx`、常见 WinSock I/O、进程与 ntdll 文件入口，以及 Linux ptrace 完整 syscall 基线和 Linux Gum manifest。
