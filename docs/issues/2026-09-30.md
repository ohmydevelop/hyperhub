# 2026-09-30

## Hook 点位后续覆盖差距

- [ ] Windows socket 仍未覆盖 RIO、`TransmitFile/TransmitPackets`、完成端口/异步取消的完整语义；已补 `sendto/recvfrom/WSASendTo/WSARecvFrom`，但仍需 Windows 源码 fixture 和统一 manifest 断言。
- [ ] Windows socket 状态缺少 `WSADuplicateSocket`、跨进程 socket 继承与 handle 复用回归；需要验证连接状态、握手状态和非阻塞状态不会丢失或串到复用 handle。
- [ ] Windows DNS 目前主要覆盖 `getaddrinfo/GetAddrInfoW`，尚未覆盖 `GetAddrInfoEx*`、`DnsQuery*` 与异步取消/完成语义；需要建立 DNS API 点位矩阵并验证 Fake-IP 释放生命周期。
- [ ] Windows TLS/信任 Hook 主要覆盖 Schannel 与系统证书链 API；OpenSSL/BoringSSL、自带证书库、certificate pinning 和直接加密实现不经过这些点位。需要区分“系统信任注入可覆盖”和“必须新增 Hook/明确不支持”的栈。
- [ ] Windows 进程与文件 Hook 依赖 Win32/ntdll 用户态入口；`RtlCreateUserProcess`、未建模的 native API 以及直接 syscall 仍需对抗 fixture 或明确边界，避免 manifest 安装成功被误解为无法绕过。
- [ ] Linux Gum 仍未覆盖 `openat2/renameat2` 等没有稳定 libc 导出或需要 syscall-level 入口的路径；直接 syscall 也不经过动态符号 Hook。已补齐 dup、常见 socket alternate I/O 和 vectored/positioned I/O，但显式 Gum 仍需明确剩余边界或增加 syscall/loader 级覆盖。
- [ ] Linux open/create Hook 对 `O_CREAT|O_TRUNC` 的多重语义仍按单一操作分类；应明确“新建”和“截断既有文件”的判定与竞态策略，并增加 create/write 规则交叉回归。
- [ ] Linux Gum 的动态符号模式仍有已记录的 vfork 后代接管风险；继续跟踪 `docs/issues/2026-09-18.md`，增加 vfork 专用 fixture 后再关闭。
- [ ] Linux Gum 根进程可能由 Frida 先行回收，launcher 在 `waitpid` 返回 `ECHILD` 时只能报告 0，导致目标真实非零退出码丢失；应从 Frida 生命周期事件取得可靠 exit status，并增加失败程序回归。
- [ ] Linux ptrace 对通过 `SCM_RIGHTS`、`pidfd_getfd` 等方式进入目标进程的 descriptor 尚无完整来源建模；应补充 descriptor ingress fixture，避免 socket/file 状态依赖创建点位才能识别。
- [ ] Linux ptrace hook report 当前按 syscall 命中计数，不能证明分支语义（协议族、成功/失败、descriptor alias、跨线程/fork、entry/exit 恢复）均被执行。应把 manifest 扩展为“点位 × 语义分支”覆盖报告。
- [ ] macOS 当前没有与 Linux ptrace/Windows Gum 等价的运行时 Hook 后端；需要明确支持边界或实现平台专属覆盖，避免跨平台文档把通用 CLI 可用性误解为 Hook 能力等价。
