# Bug（已修复）

## 文件访问阻断行为不一致

- **问题**：`.ssh` 文件读取的阻断行为不一致：部分读取方式可以阻断，部分读取方式无法阻断；无法阻断的方式会成功读取文件，未达到预期。
- **状态**：待处理。

## 测试结果

### 无法阻断（读取成功）

- `cmd.exe type`：成功，读取完整内容。
- `cmd.exe more`：成功，读取完整内容。
- `cmd.exe findstr`：成功读取并显示第 1 行。
- `ssh-keygen -F`：成功解析并显示主机记录。
- `ssh-keygen -lf`：成功读取并计算指纹。
- `certutil -dump`：成功读取文件。
- `fc /b`：成功打开并读取文件进行比较。

### 可以阻断（读取被拒绝）

- PowerShell `Get-Content`：Access denied。
- .NET `File.ReadAllText`：Access denied。
- .NET `File.ReadAllBytes`：Access denied。
- .NET `FileStream`：Access denied。
- PowerShell `Select-String`：Access denied。

## 补充说明

- 之前 CMD 读取失败是路径转义问题；修正调用方式后已成功。

## 修复记录（2026-08-31）

- 修正 Windows `NtCreateFile` 的 `CreateDisposition` 判断：`FILE_OPEN_IF` 按实际访问权限识别为读取或写入，不再统一误判为创建。
- 文件沙盒继续通过句柄、文件映射和复制句柄跟踪目标路径；读取操作在路径无法可靠解析时采用 fail-closed，并记录 `<unresolved>` 审计目标。
- 增加 `FILE_OPEN_IF`、创建、覆盖和未知路径读取的回归测试。

上述修复覆盖了 issue 中列出的 `.ssh` 文件读取路径。Windows 真实命令矩阵仍应在发布前使用实际 Agent 和目标环境完成平台验收。
