## TODO：ptrace 既有会话未接收沙盒热更新

- 现象：通过 `approve` 启用文件或子进程沙盒规则后，规则启用前已经启动的 Linux ptrace 受管进程仍使用启动时快照；新启动的受管进程会使用新规则。Gum Agent 已通过 `SubscribeSandbox` 接收运行时更新。
- 风险：安全规则热更新在不同后端上的语义不一致，旧 ptrace 会话会形成持续到进程退出的策略窗口。
- 预期：ptrace supervisor 应复用带版本的沙盒订阅/刷新协议，原子替换已编译快照，使既有会话从下一次相关 syscall 起执行新规则；已经完成的读取、已进入内存的数据和已发生的副作用无法追溯撤销。
- 回归：使用长运行 ptrace fixture，在同一 PID 存活期间热更新文件读取和子进程规则，断言更新前允许、更新后相应 syscall 被拒绝，并覆盖无效更新保留旧快照的失败行为。
