# 2026-10-16

## 已修复（源码）：配置与运行解锁封套代次不一致，重启误报密码错误或文件损坏

- 用户反馈：升级至 0.2.10 后，自动启动及连续 `hyperhub restart` 均在 Serve 启动阶段以状态 2 退出，日志为 `configuration password is incorrect or the file is damaged`；当前实例为 `/home/a/.hyperhub`，状态为 stopped。
- 只读证据：`config.bin` 和 `runtime/config-key.bin` 均使用版本 1 的加密容器，文件长度与头部声明一致；二者 KDF 参数相同，但 config ID 与 salt 不同。配置最后修改时间为本地 2026-10-15 17:51，运行封套为 2026-10-14 01:00。未读取或输出真实 API Key、管理员密码或配置明文。
- 直接原因：运行封套中的 ConfigKeyring 属于旧配置代次。启动父进程仅验证 API Key 能否打开封套；子进程加载当前配置时，`config_store::ensure_keyring_descriptor` 因代次不一致返回通用 Authentication，因而出现上述误导性错误。该错误本身不能证明配置密文损坏。
- 触发来源尚未证实：TUI `save` 在离线保存时轮换 descriptor，运行封套却在 `main::serve` 等待整个 TUI 正常返回后才刷新，存在保存后异常退出或重启的不同步窗口；现有日志不能确认用户是否经过此路径。0.2.9 到 0.2.10 未修改这些配置/解锁代码，不能将其报告为已确认的新格式兼容回归。
- 当前版本恢复办法：用户在真实终端运行 `hyperhub config`，用管理员密码成功打开后，不作修改，按 `q` 正常退出；现有正常退出路径会刷新运行封套。随后运行 `hyperhub start` 和 `hyperhub status --json`。已有权限受限的管理员密码文件时，也可使用 `hyperhub start --admin-password-file <file>`。密码不得交给 Agent。用户尚未反馈恢复结果，不能声称 Serve 已恢复。
- 待修复：配置保存成功时同步维护运行封套，覆盖离线保存、修改密码及异常退出；启动预检区分封套代次过期、API Key 错误和真实容器错误，提供可执行的恢复提示；审查刷新封套前是否已验证管理员密码，避免错误密码覆盖原有效封套。
- 回归方向：使用隔离 Home 和虚拟凭证，覆盖保存后不退出编辑器即冷启动、正常退出、密码变更/放弃、失效封套与错误 API Key。此问题属于配置持久化和 CLI 生命周期，优先使用模块及 CLI/PTY 集成测试，无需新增目标程序 Benchmark。

用户随后明确要求修改。已实现普通保存保持密钥、保存时更新运行封套、错误密码保护与过期封套预检，详细行为及验证进度见 `docs/bugfix/2026-10-16.md`。上面的 TODO 与文件时间保留为修复前证据；用户实际 Home 未由本轮实现测试修改。
