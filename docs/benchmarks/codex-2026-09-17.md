# Codex 静态程序兼容性验证（2026-09-17）

## 对象

- `codex-cli 0.154.0`；
- x86_64 static PIE；
- 文件大小约 251 MiB；
- 已 stripped，`nm` 无符号。

HyperHub 没有 Codex 名称、路径、版本、特征码或协议专用分支。该验证只把 Codex 当成普通大型 Rust 静态程序。

## 用例

原生和 HyperHub 分别执行一次真实模型对话：

```sh
codex exec \
  --ephemeral \
  --skip-git-repo-check \
  --ignore-rules \
  --json \
  'Reply with exactly: HYPERHUB_CODEX_OK'
```

HyperHub 版本仅在命令外层增加通用启动边界：

```sh
hyperhub run --runtime libhyperhub_gum_agent.so -- \
  codex exec --ephemeral --skip-git-repo-check --ignore-rules --json \
  'Reply with exactly: HYPERHUB_CODEX_OK'
```

## 结果

两组测试均：

- exit code 为 0；
- 收到 `thread.started`、`turn.started` 和 `turn.completed`；
- 最终模型消息精确为 `HYPERHUB_CODEX_OK`；
- 流式 JSONL 未损坏；

该用例实际经过静态 supervisor 的多线程、DNS、非阻塞 TCP、descriptor 和 TLS 应用数据路径。测试期间发现并修复了通用 UDP socket 分类问题：UDP `connect` 现在只记录 DNS peer，不再错误重定向到 TCP SOCKS listener。
